## 2. 原因の見立て
| 見立て | 根拠(測定・楽譜) |
|---|---|
| 設計ルール「ほぼ無音の区間を 2 か所以上」を、**BGM ごと**音が極端に小さくなる窓として実装した(依頼元の見立て) | BGM だけの 100 ms RMS の最小が、A -46.0 dBFS(曲の中央値から -26.6 dB)、B / C -60.1 dBFS(-39.7 dB)。A は 1.9–3.1 s と 11.5–11.9 s、B / C は 2.0–3.0 s と 11.6–12.2 s で BGM を大きく落としていた(A は弦・パッドを -30 dB、さらに音楽全体を -24 dB。B / C は音楽全体を -22 dB と -16 dB) |
| 場面ごとに楽器を丸ごと入れ替え、1 曲になっていなかった | B / C: ピアノ → ギター + ベース + シェイカー → 弦 → エレピ + キック + ベース → (止め)→ ピアノ + 弦 + 合唱。各パートが場面の境で止まる(ギター・ベース 6.5 s、グルーヴ 11.55 s)。A: 全編の弦 + パッドの上に、合図ごとの単発の音 |
| 主旋律が無い | A は旋律なし(合図に 1 音ずつ)。B / C は冒頭の 3 音(G5-F5-D5)だけ |
| 拍が途切れる | 音の立ち上がりのすき間の最大: A 1.86 s(11.4 s から)、B / C 2.51 s(6.94 s から = 弦だけになる区間) |
| 和音の変わり目が小節とずれる(B / C) | 6.875・8.75・11.25・12.637 s に変わる(小節の頭は 0・2.5・5・7.5・10・12.5 s) |

詳しい監査: `BGM_AUDIT_ROUND2.md`。ルールの修正: `CHANGELOG.md`(2026-10-28 第2ラウンド)。

## 3. earshot の結論(第1ラウンドまでの測定と、この判定から)
| | 内容 |
|---|---|
| **効く** | 動きに合わせた通過音(長さと頂点の時刻が ±2 ms 前後)、調に合わせた音程(±13 セント以内)、効果音バンクの即時描画とモデル不要の監査、置き方の枠組み(下地に対する大きさ・絵に対する前後・連続の間隔・山の前のステップダウン)、同期・無音・ラウドネス・拍の自動測定。**Kenney の録音と組み合わせた版が、効果音で 1 位**になった |
| **効かない** | 好み・感情・高級感の判断(earshot の critique は B・C を 23/23 としたが、BGM の不評は捉えられなかった。critique は「BGM のつながり」を測らない)。ミックスの中の音の名前の推定。realness による出どころの判定 |
| **向かない** | 紙・布・本のような「物の手触り」の録音そのもの(Kenney の録音の方が rank・realness・測定値で合っていた)。fit 系・短い UI 音の seed 違い(ほぼ同じ音になる)。小さい環境でモデルの分析を常用すること(メモリ 2.4 GB) |
| 使い方の結論 | 効果音は「earshot だけ」より「Kenney の録音 + earshot の形を合わせられる音」の併用。BGM の良し悪しは earshot では判定できないので、人の試聴で決める |
