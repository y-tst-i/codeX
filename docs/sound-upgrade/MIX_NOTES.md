数値は `qa.py` / `listen_earshot.py` の測定(`work/qa.json`、`work/earshot/`)。聴感の良し悪しは書かない(AI は聴けない)。

## 1. 既存の BGM(条件 A)の監査
A は `motion2d-hitotsuzutsu/sound/make_audio.py`。この環境で再実行すると元の音と相関 0.9999 で一致したので、ステムを監査に使った。

## 2. 新しい BGM の設計(`projects/hitotsuzutsu/score.py`、B と C で共通)
- **調と和声**: Eb メジャー。和音の変わり目を絵の合図に合わせた: 0 Ebmaj9 → 2.5 Abmaj9 → 5.0 Cm9(ステップ 1)→ **6.875 Eb/G(大チェック)** → 7.5 Abmaj9 → **8.75 Bbsus4(窓)** → 10.0 Abmaj9(グラフ)→ 11.25 Bb(今日の棒)→ **12.637 Eb add9(タイトル、着地の 70 ms 後)**。
- **場面ごとに役割の違う楽器**(BRIEF ルール 1: 楽器の系統・空間・帯域を変える):

| 場面 | 楽器(GM) | 空間(`common.room_ir`) | 帯域 |
|---|---|---|---|
| 一覧 0–3.75 | ピアノ(0)を弱いベロシティ + 3.2 kHz LP(フェルト寄り)。和音を伸ばし、揃った拍 2 から上の旋律 G5-F5-D5 | 小さく暖かい 0.7 s | LP 3.2 kHz、低域棚 -2 dB |
| 詳細 3.75–6.87 | ナイロンギター(24)の 8 分 + 指弾きベース(33)+ シェイカー(GM ドラム 70) | 乾いた 0.6 s、明るい | ギター HP 150、ベース LP 1.8 kHz |
| 大チェック〜窓 6.87–10.0 | 弦(48、横幅 0.7)、CC11 で開く → 引く → 窓でクレッシェンド | 1.6 s | LP 5.5 kHz(クリックの帯域を空ける) |
| グラフ 10.0–11.55 | エレピ(4)のシンコペーション + キック/リム + シェイカー + ベースの 8 分 | 1.2 s、明るい | エレピ HP 120 |
| 止め 11.6–12.2 | 弦の ppp だけ(完全な無音にしない) | — | — |
| タイトル 12.2–15 | ピアノの 1 音のピックアップ(12.23) → 解決和音 + 弦の内声 + 合唱(52)ごく薄く | 長く暗い 2.6 s | LP 6 kHz |

- **演奏表現**: ベロシティ ±6、拍の頭以外の発音 ±6〜8 ms(seed 固定)、ペダル(CC64)、弦と合唱の強弱(CC11)。
- **場面の弧**: 一覧は控えめ(-2.5 dB)→ 詳細で前へ → 戻りで一度引く → グラフが一番前 → 止め(-16 dB)→ タイトル。
- **合図に空ける編曲**(測定で見つけて直した。下の表)。

## 4. -14 LUFS で出す理由と、用途別の音量
**採用理由**: このスキルの既定(`BRIEF.md`)で、過去の比較もこの値で揃えた。YouTube などの配信は大きい音を下げる方向に正規化するので、-14 前後なら「下げられない・持ち上げられない」範囲に収まりやすい。比較の公平さ(3 本を同じ大きさに)にも同じ値を使った。

**この映像で測って分かった代償**: 静かな映像を -14 LUFS・真のピーク -2 dBTP(WAV、AAC 後 -1 dBTP)で出すと、頂点の余裕(PLR)は 12 dB しかない。クリックや本の音のような一瞬の音は、earshot の bed_db 通りの大きさにすると余裕を超える。結果、B の 33 件中 18 件、C の 28 件中 20 件の効果音は「頂点の上限」で大きさが決まり、リミッターも 2.1〜2.5 dB 働いている。静かで上質な映像ほど、この制約が音の「抜け」に効く可能性がある(聴感は未確認)。

**用途別に出し分けられるか**: できる。仕上げ前のミックスとステムが残るので、`common.master(mix, target, ceil_db)` の 2 つの数値を変えて書き出すだけ(映像は -c:v copy)。案:

| 用途 | 統合ラウドネス | 真のピーク | 理由 |
|---|---|---|---|
| SNS(縦型・自動再生、スマホのスピーカー) | -14 LUFS(今回) | -1 dBTP | 正規化で下げられても聞こえる大きさ。スマホ帯域(200 Hz–6 kHz)は全体との差 -1.2〜-1.6 dB(低音に偏っていない) |
| LP・Web 埋め込み(正規化なし、他の動画と並ぶ) | -16 LUFS | -1 dBTP | 頂点の余裕が 2 dB 増え、リミッターがほぼ要らなくなる見込み(未測定)。上質さを優先 |
| 社内・発表(会議室、ノート PC) | -16 LUFS、LRA を 6 LU 以下に | -1 dBTP | 部屋の雑音でほぼ無音の窓が消えすぎないよう、静と動の差を少し縮める |
| 放送(参考) | -23 LUFS(EBU R128)/ -24 LKFS(日本の ARIB TR-B32) | -1 dBTP | 放送に出す場合だけ |

-16 LUFS 版などは今回は作っていない(依頼の範囲外)。作るなら、人の試聴で -14 と -16 を同じ再生音量で比べるのがよい。

## 5. 反対意見・代案(依頼に対して)
- **数値の合わせ込みには限界がある**: 帯域の重なりを全部プラスにすると、効果音が音楽から浮く(「全部聞こえる」= 良いミックスではない)。今回は「埋もれて意味が無くなる所」だけ直し、残りは人の耳に残した。
- **earshot の critique が 23/23 でも採用理由にしない**: 基準は SaaS / AI 宣伝 7 本で、静かな紙の質感の映像とは様式が違う。A の「close 19/23」の指摘(拡大・縮小の最速点に音が無い)は具体的で、A の改善点として正しいと思うが、それも最後は耳で。
- **代案**(交絡の解消。今回は作っていない): 次は「同じ BGM で効果音だけが違う B と C」に加えて、「A の BGM + C の効果音」を作ると、効果音と音楽のどちらが効いたかを分けて聴ける。
