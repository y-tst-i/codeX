# 自己点検と機械的な検査(第3ラウンド: BGM 5 本の聴き比べ)

> この文書には、比較パックの記号と中身の対応が分かる値(記号ごとの数値・ファイルの大きさ・LRA、どの BGM にどの処理をしたか)を書いていない。
> 5 本まとめての範囲と、合格した本数だけを書く。条件ごとの数値は正解表のフォルダ(`answer_key/` の第3ラウンドのファイル)にある。**試聴の評価を書き終えてから**開く。

道具: `claude-video-skill/sound-kit/projects/hitotsuzutsu/` の `audit_round3.py`(元の BGM の点検)・`make_round3.py`(ミックス)・`finish_round3.py`(比較パック)・`qa_round3.py`(検査。`--earshot` で earshot timeline、`--publish` で条件ごとの表を answer_key/ に書く)・`bgm_metrics.py`・`qa.py`、まとめて `build_round3.sh`。
生データ: `docs/sound-upgrade/work/R3_audit.json`・`qa_round3.json`・`compare_round3_levels.json`(git の外)。ラウドネスは ffmpeg `ebur128`。
**AI(Claude)はこの 5 本を聴いていない。** 下はすべて数値の測定。

## 1. 数値で確認できた物(5 本まとめて)

| 項目 | 結果 |
|---|---|
| 長さ | 5 本とも 15.000 s(元の BGM も 5 本とも 15.000 s) |
| 映像 | 5 本とも `-c:v copy`。映像トラックの MD5 は 5 本とも元の映像と一致(`3a172d646b5c272d64092b7d2459a477`) |
| 効果音 | 5 本とも C(併用版)の仕上げ前の同じ標本。C の音程の身振り(チェレスタ・ビブラフォン)も 5 本とも同じ物 |

### ラウドネス・ピーク・クリップ・モノラル
| 項目 | 5 本の範囲 |

| 動画の統合ラウドネス / 真のピーク | -14.0〜-14.1 LUFS / 最大 -2.0 dBTP |

| WAV の標本ピーク | -2.31〜-2.32 dBFS(同じリミッター、上限 -2.3 dBTP) |
| クリップ(\|x\| ≥ 0.999 の標本) | 5 本とも 0 |
| モノラル(0.5L+0.5R)の統合ラウドネス − ステレオ | -3.2〜-4.2 dB |
| 送る物の大きさ | 動画 5 本 + BGM だけ 5 本で 28,803,855 バイト(約 28.8 MB) |

### ルール 4(静けさは効果音で、BGM は落とさない)
| 項目 | 結果 |
|---|---|
| BGM ベッドの落ち込み: ミックスの中の BGM、100 ms 窓を 10 ms ずつずらした RMS の最小と中央値の差(合格 = -15 dB 以内) | **5 本とも合格**(-10.3〜-14.2 dB) |
| 同じ測り方で 50 ms 窓(参考に同じ -15 dB で判定) | 4 本合格、**1 本が -16.7 dB で外れた**。この谷は元の BGM のファイルにある(元のファイルで -17.4 dB、谷を入れる前で -17.1 dB)。こちらの処理で作った谷ではない |
| 効果音の静けさの窓(効果音ステムの 100 ms RMS < -40 dBFS が 0.3 s 以上。始まり・終わりを除く) | 5 本とも 10 か所(合格) |

### 拍
| 項目 | 結果 |
|---|---|
| テンポ(librosa、BGM だけ) | 5 本とも 95.7 BPM(映像の 96 BPM の格子) |
| 拍の間隔(librosa)の中央値 / 最大 | 0.627 s / 0.627〜0.65 s |

| earshot timeline のテンポ / 拍の明瞭度 | 4 本は 95.9〜96.1 BPM / 0.43〜0.60。1 本は 127.8 BPM / 0.69(96 の 4/3 倍。細かい刻みを拍と取った可能性。librosa は 95.7) |

### 帯域の干渉(C の効果音の合図のうち、主な帯域が 250 Hz–4 kHz の 21 件で数える)
| 物差し | 5 本の範囲 |
|---|---|
| 120 Hz 未満の重なり(両方 -40 dBFS 超、差 6 dB 未満) | 0〜2 件(5 本で計 5 件。すべて効果音 -39.3〜-39.9 dBFS・音楽 -36.1〜-39.3 dBFS で判定の境目付近) |
| 中域で埋もれる: 頂点の 30 ms・1/3 オクターブで 効果音 − 音楽 < 3 dB(調整に使った物差し) | 2〜8 / 21 |
| 同: 30 ms・1/6 オクターブ | 1〜6 / 21 |
| 同: 頭の 120 ms・1/3 オクターブで < 0 dB | 12〜18 / 21 |

- 5 本とも残る物: 「カードが浮く」布の音(C で -8 dB に絞った、ほぼ聞こえない設計の音。BGM を下げると BGM の谷の方が目立つので、意図して空けていない)と、戻りの通過音に重ねた布の層。
- 中域の埋もれが多い BGM ほど、カードの着地・数字が回る音が BGM と同じ帯域で重なっている(BGM の編曲は変えない取り決めなので、浅い谷だけで残った分)。

## 2. ミックスのやり方(5 本とも同じ規則。どの BGM に何をしたかは answer_key に)
- BGM の大きさ: まず BGM だけを統合 -14.0 LUFS にそろえ(元の大きさの違いを直す。小さかった BGM は約 +10 dB。その BGM はそろえた後も標本ピーク -2.0 dBFS・クリップ 0・10 kHz 超の成分 -82 dBFS で、持ち上げで目立つ高い帯域の雑音・クリップは数値では見つからなかった。歪みの有無は聴いて確かめる)、次に「BGM + 身振り」を C の音楽バス(仕上げ前)と同じ大きさにして、効果音との釣り合いを 5 本でそろえた。
- 低い効果音の瞬間(大チェック・タイトル着地・詳細の着地): 200 Hz 未満だけを一瞬下げる(第2ラウンドと同じ値)。
- 中域: 効果音の頂点の 30 ms で効果音が音楽より 6 dB 上になるよう、足りない分だけ BGM のその帯域を一瞬下げる。下げる量は下げる前の BGM に対して 1 回だけ求め、時間の重なる窓は 1 つにまとめた。**上限 -6 dB、立ち上がり・戻り 50 ms(なめらか)、重なる窓 0**。窓の数は 1 本あたり 5〜8。
- 編曲(音を足す・消す・並べ替える)はしていない。
- 終わり方: 元の BGM の最後の 2 s の調が全体の調と同じで、最後の 100 ms が中央値より 9 dB 以上下がっている物は「主音に解決して終わる」とみなし、そのまま。そうでない物には、終わりの静止(13.6 s)の後に短いフェード(14.0 s から 1.0 s)を足した。
- 仕上げ: 第2ラウンドと同じ(音楽バスのリミッター → -14 LUFS / -2 dBTP)。仕上げのリミッターの削り量は 1.1〜4.3 dB(効果音の頂点の所。BGM の密度で違う)。

## 3. 比較パックのそろえ方と、伏せ方
- 5 本とも同じ手順(`finish_round3.py`): WAV → ゲインで -14.0 LUFS → 同じリミッター(-2.3 dBTP)→ 動画は AAC 192 kbps・映像 -c:v copy、BGM だけは AAC 160 kbps の m4a。
- BGM だけの音声は、谷を入れる前の BGM から作った(身振りは含めない。5 本同じ扱い)。
- 伏せ記号は前のラウンドの記号・頭文字と重ならない物を新しく引き、git の中に固定(`answer_key/round3_key.json`)。作り直しても同じ記号。対応表が無い時は `--publish` が無ければ作らずに止まる。
- 評価用紙: 列は記号の英字順。順番の表は 10 行(どの 1 本の直後にどの 1 本が来る組も 2 回ずつ、どの位置にも各 1 本が 2 回ずつ)。中身の手がかりになる文なし。
- 消せない手がかり(記号つき)は `answer_key/ANSWER_KEY_ROUND3.md` にだけ書いた。
- 同じ手順でパックを作り直し、10 ファイルとも MD5 が一致することを確かめた。

## 4. 人の試聴が必要な項目(AI は音を聴けない。ここは未確認)
- ① 1 曲としてつながって聞こえるか ② まとまり(ごちゃごちゃしていないか) ③ 効果音と合うか(音の高さ・響きのぶつかり) ④ 聴き疲れ ⑤ 総合の順位。BGM だけの音声で同じく ①②④⑤ と音の質感。
- 効果音の瞬間に BGM の帯域を一瞬下げた所(最大 -6 dB、50 ms)が「揺れ」や「抜け」に聞こえないか。
- 終わりにフェードを足した BGM が、タイトルの所で落ち着いて聞こえるか、途中で切ったように聞こえるか。
- 音の質感(こもり・ざらつき・不自然さ)。
