> この文書には、比較パックの記号と中身の対応が分かる値(記号ごとの数値・ファイルの大きさ・LRA、どの BGM にどの処理をしたか)を書いていない。

生データ: `docs/sound-upgrade/work/R3_audit.json`・`qa_round3.json`・`compare_round3_levels.json`(git の外)。ラウドネスは ffmpeg `ebur128`。
**AI(Claude)はこの 5 本を聴いていない。** 下はすべて数値の測定。

### 効果音の頂点(仕上げのリミッターがどれだけ潰したか)
測り方: 仕上げ前の和(音楽ステム + 効果音ステム)を出来上がりの WAV に 5 ms ごとの最小二乗のゲインで当てはめ、効果音ステム × そのゲインの標本ピークを、合図の同期点 -20 ms〜+100 ms で取る(独立レビューと同じ方式)。同じ名前の合図は 1 つの窓。

| 項目 | 5 本の範囲 |
|---|---|
| 仕上げのリミッターの削り量(mix.wav) | 0.0〜1.45 dB(前の版 1.1〜4.25 dB) |
| 合図ごとの効果音の頂点の差(5 本の最大 − 最小、mix.wav、25 合図) | 中央値 0.4 dB。1 dB を超えるのは 1 合図(段のチェック 3 つ目、1.3 dB)。次は 0.76 dB(前の版は最大 4.8 dB) |
| 同じ物差しで比較パックの WAV(さらに -2.3 dBTP のリミッター) | 中央値 0.4 dB。1 dB を超えるのは 3 合図(段のチェック 3 つ目 1.6 dB、カードが一覧に戻る所と数字が回る所(同じ窓)1.06 dB) |
| 0.4 dB の差の大部分 | 仕上げのゲインの違い(12.9〜13.3 dB)。リミッターが掛からない合図でも、この分だけ違う |

## 2. ミックスのやり方(5 本とも同じ規則。どの BGM に何をしたかは answer_key に)
- 基準の BGM も、生成 BGM 4 本と同じ規則でミックスし直した(曲は第2ラウンドと同じ)。
- BGM の大きさ: BGM だけを統合 -14.0 LUFS にそろえ、低域の下げの後、「BGM + 身振り」を C の音楽バス(仕上げ前)と同じ大きさにした(効果音との釣り合いを 5 本でそろえる)。小さかった BGM(約 +10 dB)は、そろえた後も標本ピーク -2.0 dBFS・クリップ 0・10 kHz 超の成分 -82 dBFS で、持ち上げで目立つ高い帯域の雑音・クリップは数値では見つからなかった。歪みの有無は聴いて確かめる。
- 低い効果音の瞬間(大チェック・タイトル着地・詳細の着地): 200 Hz 未満だけを一瞬下げる(第2ラウンドと同じ値: -15 / -6 / -20 dB)。
- 中域の谷: 効果音の頂点の 30 ms で効果音が音楽より 6 dB 上になるよう、足りない分だけ BGM のその帯域を一瞬下げる。下げる量は下げる前の BGM に対して 1 回だけ。**間が 0.15 s(立ち上がり・戻りの 3 倍)未満の窓は 1 つにまとめた**(前の版は間が 0.101 s の窓が 2 組あり、一瞬 0 dB に戻っていた)。**帯域の上限は 4.5 kHz**(前の版は 16 kHz まで広がる窓があった)。上限 -6 dB、立ち上がり・戻り 50 ms(raised cosine)、重なる窓 0。窓の数は 1 本あたり 4〜8。
- BGM だけのリミッター: 仕上げのゲインの後で BGM だけの頂点が -3.0 dBFS 以下になるように(削り量 0.6〜3.2 dB)。音楽バス(BGM + 身振り)のリミッターは使わない(身振りを条件ごとに違う量で削らないため)。
- 効果音の頂点を守る下げ(新しい): 効果音の同期点と身振りの発音の時刻の窓(-30 ms〜+100 ms)で、仕上げのゲインの後のミックスの頂点が -2.5 dBFS(効果音・身振り・部屋だけでそれを超える窓は、その頂点 + 0.5 dB)を超える所だけ、BGM を全帯域で浅く下げる(上限 -6 dB、50 ms の raised cosine、間が 0.15 s 未満の隣は浅い方の深さでつなぐ)。全帯域で足りない所は、さらに 40–250 Hz だけを下げる(上限 -6 dB)。その結果 BGM ベッドが深くなりすぎる所は、近くの下げを 0.5 dB ずつ浅くした(優先の順: ルール 4 の 100 ms > 効果音の頂点 > 参考の 50 ms)。
- **重なった時の合計**: 上の 3 つ(低域の一瞬の下げ・中域の谷・頂点を守る下げ)と BGM だけのリミッターは別の処理なので、同じ瞬間に重なると合計は -6 dB より深くなる。BGM だけの音声に対してミックスの中の BGM が下がった量の最大(30 ms、14.0 s まで): 40–250 Hz -12.4〜-17.1 dB(-15〜-20 dB の低域の一瞬の下げを含む)、250 Hz–4 kHz -6.3〜-11.5 dB、4–16 kHz -6.0〜-7.7 dB。
- 編曲(音を足す・消す・並べ替える)はしていない。
- 終わり方: 記録で決めた。作曲した終わり方の BGM はそのまま。生成 BGM は、20 s で作って 15 s に切った物と、15 s で作って最後まで減衰しない物で、どちらも作曲上の終わりではないので、終わりの静止(13.6 s)の後に短いフェード(14.0 s から 1.0 s)を足した。調は平行調(例: C 短調と Eb 長調)を同じ扱いにした。
- 仕上げ: -14 LUFS / -2 dBTP(第2ラウンドと同じ。音楽バスのリミッターだけ使わない)。

## 3. 比較パックのそろえ方と、伏せ方
- 5 本とも同じ手順(`finish_round3.py`): WAV → ゲインで -14.0 LUFS → 同じリミッター(-2.3 dBTP)→ 動画は AAC 192 kbps・映像 -c:v copy、BGM だけは AAC 160 kbps の m4a。
- BGM だけの音声は、**低域の一瞬の下げ・中域の谷・頂点を守る下げ・BGM だけのリミッターの前**の BGM から作った(終わりのフェードは含む。身振りは含めない。5 本同じ扱い)。前の版は低域の一瞬の下げ(200 Hz 未満を -15 / -20 / -6 dB)が入っていた。
- 伏せ記号は第3ラウンドで引いた物のまま(`answer_key/round3_key.json`)。対応表が無い時は `--publish` が無ければ作らずに止まる。
- 評価用紙: 列は記号の英字順。順番の表は 10 行(どの 1 本の直後にどの 1 本が来る組も 2 回ずつ、どの位置にも各 1 本が 2 回ずつ)。中身の手がかりになる文なし。試聴する人には `compare_round3` のフォルダだけを渡す、と書いた。
- 消せない手がかり(記号つき)は `answer_key/ANSWER_KEY_ROUND3.md` にだけ書いた(音声のビットレートの違いも)。

## 4. 人の試聴が必要な項目(AI は音を聴けない。ここは未確認)
- ① 1 曲としてつながって聞こえるか ② まとまり(ごちゃごちゃしていないか) ③ 効果音と合うか(音の高さ・響きのぶつかり) ④ 聴き疲れ ⑤ 総合の順位。BGM だけの音声で同じく ①②④⑤ と音の質感。
- 効果音の瞬間に BGM を下げた所(中域の谷と、頂点を守る全帯域・低域の下げ。重なると合計 -6 dB より深い所がある)が「揺れ」「抜け」「ポンピング」に聞こえないか。
- BGM だけのリミッター(最大 3.2 dB)で BGM の頭が潰れて聞こえないか。
- 終わりにフェードを足した BGM が、タイトルの所で落ち着いて聞こえるか、途中で切ったように聞こえるか。
- 音の質感(こもり・ざらつき・不自然さ)。
