### 帯域の干渉(C の効果音の合図 21 件のうち主な帯域が 250 Hz–4 kHz の物で数える)
| 物差し | 基準 | 新しい 2 案 |
|---|---|---|
| 120 Hz 未満の重なり(両方 -40 dBFS 超、差 6 dB 未満) | 0 件 | 0 件と 2 件(2 件とも効果音・音楽が -37〜-40 dBFS で、判定の境目付近) |
| 中域で埋もれる: 頂点の 30 ms・1/3 オクターブで 効果音 − 音楽 < 3 dB(調整に使った物差し) | 2 / 21 | 2 / 21 と 5 / 21 |
| 同: 30 ms・1/6 オクターブ(別の物差し) | 0 / 21 | 2 / 21 と 5 / 21 |
| 同: 頭の 120 ms・1/3 オクターブで < 0 dB(別の物差し) | 16 / 21 | 17 / 21 と 12 / 21 |

- 新しい 2 案で残る物: 「カードが浮く」布の音(C で -8 dB に絞った、ほぼ聞こえない設計の音。BGM を下げて出すと BGM の谷の方が目立ったので、意図して空けていない。-12 dB 前後)、戻りの通過音に重ねた布の層(-0.9 dB と -3.1 dB)、もう 1 案ではカード 1 枚目・詳細の着地・今日の棒(+2.3〜+2.6 dB、3 dB の目安の境目)。
- 空け方: まず編曲で(効果音の瞬間のオスティナート・打楽器を弾かない、ベースを手前で切る、エレピの和音を短くする・裏に移す)。残りだけ、BGM のその帯域を一瞬下げた。下げる量は**下げる前の BGM に対して 1 回だけ**求め、時間の重なる窓は 1 つにまとめて上限 -6 dB、立ち上がり・戻りは 50 ms(なめらか)。窓の数は重複を除いて 6 と 8(前の版は同じ窓に -6 dB が 2 回掛かり最大 -12 dB、重複を除いて 9 と 13 だった)。
- タイトルの解決(12.5 s): 前の版は 200 Hz 未満を -20 dB・0.25 s 下げて主音が約 0.4 s 消えていた。→ 下げ幅 -6 dB・0.12 s に浅くし、編曲で空けた(主音を拍 20 に Eb3 で置き、低い Eb2 は着地の音の後の 8 分裏 12.81 s から。もう 1 案は主音をエレピの Eb4 に任せ、Eb2 は同じく 12.81 s から)。前の小節の低音はタイトルで切る。

### 効果音の大きさについて(正確に)
効果音は 3 本とも **C の同じ標本(仕上げ前)**。仕上げで掛かるゲインは 3 本で 12.9〜13.1 dB と少し違うので、仕上げ後の効果音の大きさは最大 0.2 dB 違う。効果音の静けさの窓の端も 0.1 s ずれる所がある(仕上げのリミッターと BGM の残り方による)。「効果音は同じ」は「仕上げ前の標本が同じ」の意味。

## 2. 比較パックのそろえ方と、伏せ方
- 3 本とも同じ手順(`finish_round2.py`): WAV → ゲインで -14.0 LUFS → 同じリミッター(-2.3 dBTP)→ 動画は AAC 192 kbps・映像 -c:v copy、BGM だけは AAC 160 kbps の m4a(フェードつき)。
- 伏せ記号は第1ラウンドと重ならない物で、git の中に固定(`answer_key/round2_key.json`)。作り直しても同じ記号。対応表が無い時は `--publish` が無ければ作らずに止まる。
- 評価用紙: 列は記号の英字順、順番は 3 本の全順列の 6 行(直前の 1 本の持ち越しもそろう)、条件の手がかりになる文なし、この QA は「評価の後に」と案内。
- 消せない手がかり(基準が第1ラウンドと同じミックス、LRA の差、BGM だけの音声のリミッター量、ファイルの大きさ)は、記号つきで `answer_key/ANSWER_KEY_ROUND2.md` にだけ書いた。
- 交絡: 3 本は BGM だけが違う。ただし新しい 2 案には、効果音に合わせて BGM を空ける処理(編曲と、一瞬の帯域の谷)も入っているので、「曲の違い」と「ミックスの処理の違い」は分けられない。

## 3. 人の試聴が必要な項目(AI は音を聴けない。ここは未確認)
