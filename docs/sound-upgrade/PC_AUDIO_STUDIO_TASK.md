## やること
1. **確認(生成の前に、報告に書く)**:
   - 実際に使えるモデル名・バックエンド(CPU)・1回あたりの生成時間(記録があれば)・メモリ使用。
   - **ライセンス**: `AUDIO_STUDIO_PLAN.md` §1 の条件(Stable Audio 3 の商用利用は、年間売上100万米ドル未満+Stability AI への登録が要る、など)を、モデルページで再確認し、この利用者の状況に当てはまるかを**事実だけ**で書く(当てはまるかの最終判断は利用者)。**利用可否が不明な生成物は、商用の動画に組み込まない**。今回は社内の比較試聴だけに使う。
2. **BGM を 4 案、生成する**(各 **15.0 秒**。サンプルレートはモデルの既定のままでよい。最長が足りなければ、長く作って 15.0 秒に切る/つなぐ手順を報告):
   - 用途: 架空のタスク管理アプリ「ひとつずつ」の15秒の紹介動画(画面の動きが主役、静かで紙のような手触り、やさしく軽やか)のBGM。
   - 音楽の条件: **歌・声なし(インストゥルメンタル)**/テンポ約 96 BPM/調は変ホ長調(E♭)寄り、最後は主和音で解決する/**最初から最後まで途切れず1曲として流れる**(途中で音が消えたり、極端に小さくならない)/全編で拍が一定/楽器は多すぎず(2〜4種類。ピチカート、マリンバ、軽いエレピ、やわらかいベースなど。ピアノ+弦+打楽器を全部重ねない)/効果音(クリック、紙、カードの着地)が上に乗るので、中域をあまり埋めない/音量は大きすぎず、ダイナミクスの差は小さめ。
   - 4案は、方向性を変える(例: ①軽いピチカートとマリンバ ②やわらかいエレピとベース ③ギターの爪弾き ④ミニマルなシンセのパッド+軽いリズム)。各案で、プロンプト(文章)・シード・モデル・生成にかかった時間を記録する。
   - 各案を、できれば**2回ずつ**生成して、よい方を残す(同じプロンプトでも結果が変わる)。無理なら1回。
3. **聴けない代わりに、数値で確認**(PC の Python があれば。無ければ省略可): 長さ、無音の窓(100 ms の RMS が曲の中央値から -15 dB を下回る所があるか)、ラウドネス(LUFS)、ピーク、ほぼ同じ音量で続くか。結果を表で報告。**AI は音を聴けないので、聴感の評価は書かない**(「良さそう」と書かない)。
4. **成果物の置き場**: このリポジトリの `docs/sound-upgrade/audio_studio_pc/`(新規フォルダ)に、**WAV(または元の形式)の15秒の BGM 4案**(`D1.wav`〜`D4.wav`)、`generation_log.json`(各案のプロンプト・シード・モデル・時間)、`REPORT.md`(確認事項、ライセンスの事実、数値、つまずき)を置く。大きな物(モデル、キャッシュ、全生成物)は入れない。
5. **push**: 新しい枝 `pc/audio-studio-bgm`(`claude/sound-upgrade` から作る)に commit して push する。**main にマージしない。PR は作らない。** push できない場合は、`REPORT.md` の最後に、そう書き、利用者が GitHub の画面から、上の4ファイルをアップロードできるように、置き場所のパスを伝える。
