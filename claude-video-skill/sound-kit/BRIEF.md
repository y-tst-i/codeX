# 音の作り方(Codex 向けの1枚)— 映像に音(BGM・効果音)を付けるとき

このフォルダ(`sound-kit/`)の音づくりの要点。Claude 専用の話(担当エージェントなど)は入れていない。
**試験の結果**: 同じ映像に、ブラウザの合成音だけの音と、この方法の音を付けて名前伏せで比べると、この方法のほうが「絶対良い」と判定された。合成音だけだと単調になる。

## 1. 準備(1回だけ)
```bash
# Linux(Debian/Ubuntu系)。macOS は brew install fluidsynth、Windows は fluidsynth と ffmpeg を別途
sudo apt-get update && sudo apt-get install -y fluidsynth musescore-general-soundfont-lossless ffmpeg
pip install pretty_midi mido numpy scipy
```
- 音源ファイルは MuseScore General(MIT・一部CC0)。無ければ FluidR3 GM でもよい(`SF2=/path/to.sf2` で指定)。
- 無料の道具だけを使う。有料サービス・ログインが要るものは使わない。

## 2. 道具(このフォルダの `tools/`)
- `midi_render.py` … MIDI を本物の楽器音で鳴らす(`render()`)、場面ごとの残響・帯域の加工(`scene_fx()`)。GM の音色番号の早見表がファイル冒頭にある。
- `sfx_lib.py` … 録音済みの効果音(CC0、282個、`tools/assets/sfx-cc0/`)。`python3 tools/sfx_lib.py find <語>` で検索、`import sfx_lib as S; S.load("name", sr=44100)` で読み込み。
- `assemble.sh` … 場面の動画を連結して音を付け、-14 LUFS に整える(2回通しの loudnorm)。`sync_check.py` … 映像と音の同期を数値で確認。

## 3. 設計ルール(これが質を決める)
1. **場面ごとに、楽器の系統・空間(残響の長さと暗さ)・帯域(ローカット/ハイカット)の3つを変える。** 隣り合う場面で同じ系統を使わない。全体に同じ残響・同じ処理をかけない。
2. **3層に分ける**: 音楽(MIDI+楽器音源)/環境音(合成:ピンクノイズを帯域で絞る。白色雑音は高域に偏るので避ける)/効果音(録音素材)。
3. **「コードで作った音」の定番を避ける**: 純音の単発ピン、サイン波のスイープ(ピューン)、白色ノイズの雨。禁止ではないが、**1本に最大2回**。合成音は全体の**3割以下**。効果音は録音素材に差し替えるか重ねる。
4. **静けさは効果音で作る**: 効果音をほぼ鳴らさない区間を2か所以上作る(静けさがあるから山が効く)。**BGM(ベッド)は落とさない**: 1曲として切れ目なく流し、小さくしても聞こえる状態を保つ(目安: 仕上げ後の BGM の RMS を **100 ms の窓を 10 ms ずつずらして**測り、最小が曲の中央値から -15 dB 以内。ゼロや -40 dBFS 級の落ち込みにしない。区切り窓で測ると谷が隠れる)。静けさは、BGM を消すのでなく、効果音を減らす・音楽の密度を下げる(音数・楽器を減らす)・音域を絞ることで作る。
   (2026-10-28 修正。**利用者の判定**(1回・1人): 「全体的にBGMがなんともいえない。途中途中無音になるところもあるし、BGMとしての繋がりが無くて聞き心地がよくなかった」。**見立て**(判定ではない): BGM ごと -16〜-30 dB 落とす窓が「途中途中無音」の原因で、場面ごとの楽器の入れ替え・主旋律が無いこと・拍の途切れが「繋がりが無い」の原因)
5. **BGM(ベッド)は切れ目なく流し、静かな所は下げる**(ゼロにしない)。映像の山(閃光・衝撃)に音の山を合わせる。
6. **Jカット・Lカット**: 次の場面の音を先に入れる/前の場面の音を少し残す。場面の切れ目で音も完全に切り替えない。
7. 映像の**合図(cue)の時刻表**を先に作り(映像のコンタクトシートと、あれば cue sheet から)、音はその時刻に置く。音は毎回同じ結果になるよう、乱数は seed 固定。

## 4. 仕上げの目標
- 統合ラウドネス **-14 LUFS 前後**、真のピーク **-1 dBTP 以下**。AAC にすると少しピークが上がるので、最終ファイルで測る。
- 映像は再エンコードせず `-c:v copy` で結合する(画質を落とさない)。
- 確認は数値で(ffmpeg の `ebur128`、`sync_check.py`)。**AI は音を聴けない**ので、最終判断は人の耳に任せ、そう報告する。

## 5. 既知の改善余地
- 音の幅(LRA)が狭くなり、ヒット音が詰まって聞こえることがある。
- BGM の低音が強いと、場面ごとの音色の違いが小さくなる。

## 6. Codex への依頼のひな形(そのまま貼れる)
```
この映像(◯◯.mp4)に、音(BGM+効果音)を付けて。
sound-kit/BRIEF.md を最初に読んで、そのルールと道具(tools/)に従うこと。
- 映像は再エンコードせず、音だけ作って -c:v copy で結合し、◯◯_sound.mp4 にする
- 場面ごとの合図表を、映像のコンタクトシートから先に作ってから音を作る
- 音量は -14 LUFS、ピーク -1 dBTP 以下。数値(LUFS・ピーク・効果音の静けさの位置・BGM ベッドの最小レベル・純音ピンの回数)を報告する
- 無料の道具のみ。作った make_audio.py(seed 固定)も残す
```
