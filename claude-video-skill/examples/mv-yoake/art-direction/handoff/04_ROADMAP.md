# 04 開発ロードマップ — 最小改修・高品質検証の順序

| Phase | 作業 | 成果物 | 合格条件 | 失敗時 |
|---|---|---|---|---|
| 0 現状監査 | 現行SKILL/CLAUDE/lock、制作コード、素材、既存QA、Git差分を確認 | `CURRENT_AUDIT.md` | 何が既存で何が不足か説明可能 | 新規実装を停止して調査 |
| 1 設計体系の統合 | HyperFrames creative, frame.md, picker等の導入状況とAPI差分調査 | `REUSE_VS_BUILD.md` | 重複機能0または合理的な理由 | 独自レイヤを撤回・修正 |
| 2 美術ブリーフ | 『夜明けの回路』に何が必要か、3方向の実質的な違いを定義 | `BRIEF.md` `CANDIDATES.json` | 同じ絵の色替えでない | 方向性を再提案 |
| 3 スタイルフレーム | 3案各1枚 → 選定案の8/16/40秒、clean/final | 画像・HTML/SVGソース・レビュー | 文字・主役・構図が静止画として成立 | 動画化を止めて美術修正 |
| 4 アニマティク | 6秒の短い検証、楽曲との同期 | MP4・event map | 変化に意味、時刻seek再現性 | 動きより演出を修正 |
| 5 本編統合 | 既存53秒の必要なショットだけ再制作 | v2 MP4、旧版対照表、変更ログ | 音・尺・画・美術一貫性 | 部分戻し、再試験 |
| 6 汎用スキル化 | 企業PRとSNS/MVの別題材で試験 | 2作品、QA表、次回改善 | スタイル選択が題材ごとに変わる | MV用の特殊ルールを分離 |

## Phase 0 現行監査のコマンド例（必要に応じて）
```bash
pwd
find . -maxdepth 3 \( -iname '*SKILL*.md' -o -iname 'CLAUDE.md' -o -iname 'package.json' \) -print
git status --short
node --version
ffmpeg -version
npx hyperframes --help
```
実際のパス、バージョン、コマンドの有効性はClaude Code側で確認。`npx` がネットへアクセスする場合にはローカルバイナリ優先。既存環境に予期しないパッケージ導入をしない。

## Phase 3 Styleframeの最低提出物
- `style_a_08s_clean.png`, `style_b_08s_clean.png`, `style_c_08s_clean.png`
- 各案の設計根拠と「これが他案と本質的に違う理由」
- 選定後 `selected_08s`, `selected_16s`, `selected_40s` 各 `clean/final`

## Phase 4 6秒テストで調べること
- ファーストフレームで絵が成立するか
- カット間で視線が連続するか／意図した対比があるか
- テキストが音に適切に同期しているか（実音源が入手可能で許諾がある時のみ）
- カメラは画を引き立てているか、動かすために動かしていないか
- 同じ時刻を正順/逆順/ランダムseekして同じ画面になるか
- 素材の再利用条件と権利台帳が整っているか

## 工数を無制限に増やさないための打切り条件
- 3案で主役が見えない → 描画エンジン改善ではなくBriefを見直す。
- 強い静止画ができない → 53秒レンダリング禁止。
- コードのみのルートが視覚的に成立しない → 素材ベースに切り替える。ただし権利のない素材は使わない。
- 品質改善がないまま同じ操作を2回繰り返す → 制作方式自体を再選択。
- sourceの利用条件が不明 → 使用禁止・代替を検討。

## レビュー担当者が未アクセスの場合
技術検証だけで `COMPLETE` としてはいけない。`TECH PASS / ART PENDING` を使う。第三者レビューがなくても自己レビューの根拠画像・コメントを提出し、ユーザー最終確認がない旨を明記。
