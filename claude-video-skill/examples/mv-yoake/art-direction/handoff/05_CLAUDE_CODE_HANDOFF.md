# Claude Codeへの正式指示：Art Direction First / 既存動画制作スキル強化

## 役割と到達目標
あなたは**アートディレクター、モーションディレクター、テクニカルディレクター、品質責任者**を兼ねる。最優先は、テーマや楽曲から、コード実装が容易かどうかに左右されず「作品に最もふさわしい美術表現」を判断できる動画制作スキルを実現すること。

**ユーザーの明示した核：『高品質な映像＝リアルな3Dではない』。**
現行MV『夜明けの回路』では、都市を汎用的な立方体群、同形の窓、電子回路の線で表現した背景が「ポリゴン臭く安っぽい」と評価されている。課題は「3Dをもっとリアルに」だけではなく、**美術表現の選択とアートディレクションの不在**にある可能性を検証し、汎用スキルの初稿品質を改善すること。

## 最初に絶対に行うこと — 現行の実装監査
現行のスキルや環境はこの引き継ぎでは確認できていない。**実際にソースを読まずに開発を開始してはいけない。**

- `pwd`, リポジトリツリー、`SKILL.md`, `CLAUDE.md`, `AGENTS.md`, package/lock、HyperFramesの設置版、FFmpeg、レンダラ、GSAP等を確認。
- 旧プロンプト／スキル構成を確認。特に過去のMV研究・ゲームティザー研究・3D品質研究の引き継ぎ資料に実装済み機能があるか調べる。
- **公式HyperFramesの `hyperframes-creative/references/visual-styles.md`, `design-picker.md`, `design-spec.md`, `video-composition.md`, `typography.md`, `general-video/SKILL.md` が現在環境に存在・利用できるか確認。** ローカル版の仕様を優先。
- `frame.md` / `design.md` / `DESIGN.md` の優先順位を確認。既存のブランド正本を無断上書きしない。
- 現行2D/3D/音声・動画レンダリングの回帰テストを確認し、Git未コミット変更を保護。
- 機能が既存の場合は再開発せず、**既存機能を組み合わせる薄いオーケストレーション層**だけ追加する。

**Audit成果物**: `CURRENT_AUDIT.md`（証拠パス付き）・`REUSE_VS_BUILD.md`・修正対象リスト・ベースライン動画/画像の固定・安全な作業ブランチ。

## 重要な設計上の禁止
- 「サイバー都市だからBoxGeometryを配置」「未来的だからグロー・光の粒子」「MVだから文字を浮かべる」など、**名詞と簡易図形の機械的な対応**で美術決定しない。
- かといって3Dや幾何学的な表現を一律禁止しない。意図があり美術的に成立するものは許可。
- 使用素材の権利確認なしに外部画像、既存MVの音楽、他者のロゴ、フォント等を組み込まない。
- 確認していない実装状況・スクリーンショット・レンダリング結果を「検証済み」と記載しない。
- ユーザー提供MP4の元データ/良いショット、既存制作スキル・サウンドキットを無断削除・上書きしない。
- GIF/PNG/写真素材の導入を必須としない。**コードだけで美しい絵ができるならその案を選ぶ。**
- 画質に効果がない実装を増やさない。新エフェクト、新シェーダー、新エンジン追加は最終手段。

## Phase 1. Brief → 視覚言語の発見
今の『夜明けの回路』を題材に、作品が何を感じさせたいかを1文で記述。共通モチーフ「暗闇／回路／光／夜明け」を保持しつつ、少なくとも3つの**技法ではなく作品の意味が異なる美術方向**を作る。

`examples/direction_candidates.example.json` は仕様例であり正解ではない。専門判断でより良い案に置き換えてよい。その場合は理由と採否を明記する。

各案に：
- 視覚的な主役・象徴的物体
- 余白・シルエット・形・筆致・色の物語
- タイポグラフィのルール
- 読み手の視線経路
- 「実装しやすいから」の選択がないかという自己批評
- エンジン/素材選択・導入のコスト・権利の扱い
を記載する。

## Phase 2. 画像審査で選定
- 同じ8秒相当の意味から3方式の**スタイルフレーム3枚**を制作。各フレームの`clean`（光・FX低減）と`look`を用意。
- 単に色違いの案なら未提出扱い。
- 3案の美術審査を実施し、失敗を具体的に秒数・画像・理由で報告。外部評価やユーザー評価がない場合はART PENDINGとする。
- 選定案の8/16/40秒を元フレームと横並びに比較。
- 26〜28秒の強い文字構図、49秒以降の夜明け色調とどう接続するかを明示。

**強いスタイルフレームができない間は、53秒の再レンダリングに進まない。**

## Phase 3. 実装方法の比較
候補：SVG+GSAP、Canvas 2D、CSS、必要なときのみthree.js/WebGL、レイヤー化した2.5D、権利確認済み写真・イラスト。好みに基づいて技法を先に固定しない。

レビュー基準：
- サイズ1920×1080で文字・主役・光・奥行きに意味があるか
- 540px幅に縮小しても主役が伝わるか
- 絵が先に成立し、動きが意味を増しているか
- 同じ絵の色替えを異なるカットとして量産していないか
- 既存フォントのロード・埋め込み、タイムシーク、素材権利が再現できるか

## Phase 4. 6秒モーション試作
- 選定フレームで **6秒/30fps/180フレーム** のカットを制作する。
- 動きは、主役の状態変化／文字の変形／次カットへの意味ある転換を重視。カメラ移動だけで成立させない。
- 音源があり使用許諾がある時のみ、音・歌詞と同期する。BPMの検出結果をすべて演出へ直結させない。
- HyperFramesの設置版で所定のseek契約を守り、正順/逆順/ランダムアクセスで同フレームの描画が一致するか確認。
- 技術的検査：尺、音源、フォント、黒フレーム、トランジション、権利、lint/check（使用可能なら）。

## Phase 5. 本編統合と汎用化
- 元MVに戻し、8/16/40秒等の失敗背景を局所的に改善。良い箇所を守るため旧版との比較表を添付。
- 53秒全体の美術・色彩・時間のつながりと、タイポグラフィの一貫性を再検証する。
- 最後に企業PRと別MV/解説動画の**少なくとも2題材**を使い、表現ルートの選択能力を検査。元MVだけの特化コードで終わらない。
- `SKILL.md`は短いトリガー/手順とし、長文参照は`references`へ分割。既存スキルの置換を避ける。

## 完了条件と停止条件
- **技術PASS ≠ 美術PASS**。静止画の美術にユーザー承認がない場合は「未承認」と報告。
- 意図しないローポリ、反復した簡易ビル群、安易な白飛び、意味のないパーティクルを発見したら、より多くの装飾を追加する前に企画・形を見直す。
- 2度の局所改修で改善しない場合は採用した表現方式を切替える候補を出す。
- 実装の安全性、外部素材の許諾、現行環境の影響が不明なら明示し、無断で破壊的変更を実行しない。
- プロダクションの可否は「美術」「技術」「権利」をそれぞれ明記して判定する。
