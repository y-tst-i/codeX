# 08 旧研究パッケージとの違い — 言い直しだけで終わらせない

対象：既存の以下資料（このセッションで内容を確認）
- `mv_motion_research_handoff_20261030/03_CLAUDE_CODE_HANDOFF.md`
- `mv_motion_research_handoff_20261030/01_RESEARCH.md`
- `game_teaser_2d_research_20261030/02_DEVELOPMENT_ARCHITECTURE.md`

## 以前から既に書かれていたこと
- 3つの美術方向性、スタイルフレーム、絵コンテ、LookDev、音楽同期、品質検査。
- FXを増やす前に構図を評価すること。
- 既存スキルの監査と破壊防止、素材の権利確認。

**したがって「美術工程を新設する」だけでは以前の指示書の繰り返しになってしまう。** 今回は工程を**必須ゲート化**し、3Dへの無意識な誘導を断つことが増分。

## 今回追加したい本質的な差分
| 問題 | 旧資料の傾向 | 今回追加する仕組み |
|---|---|---|
| 美術案が形式的になり得る | 3案を作ると書いてある | expression_mode/主役/メタファーの差をJSONとレビューで明示。単なる色替えを不合格にする |
| 技術選定が先行する | 2D/2.5D/3Dの各技法が多い | 「感情・主役・造形の良さを先に比較」というルーティング決定を正本化 |
| スタイルフレームは提出できても不合格時に進んでしまう | 先に良い絵を作ると書いてある | `TECH_PASS_ART_PENDING`とし、合格前のフルレンダリングを止める |
| 簡単な直方体CGへ流れやすい | 一般的な高品質ルール | 8/16/40秒の**実作品の失敗例**をアンチパターン化し、毎回照合する |
| 公式HyperFramesの美術機構と重複する恐れ | 個別コンポーネント追加の構想 | official `design-picker`, `frame.md`, `visual-styles` を先に監査して流用 |
| いい作品を見ても技術へ還元できない | 作例調査中心 | 静止画比較→批評ログ→技術候補の選択→局所実装→再審査を再利用可能なプロセスにする |

## 新規実装は小さくする
推奨は巨大な`art_engine`を作ることではない。まず既存HyperFramesのcreative機能と、ユーザーの現在のスキルがどこまで備えているかを差分監査する。足りない場所だけ、候補データと審査ゲートを追加する。内部APIやインストール版が不明のまま新規ファイル配置を決めつけない。
