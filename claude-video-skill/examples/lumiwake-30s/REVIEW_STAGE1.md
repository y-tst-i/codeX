## 機械的に確かめたこと
- 3枚とも 1920×1080。同じ URL で2回描いて md5 が一致(sf1・sf3 で確認。乱数は seed 付き、時刻 t の純関数)。
- 効果を切っても構図・主役・危険・数字は残る(fx_compare)。
- 540px でも主役・稲妻・PERFECT・ロゴは読める。HUD の小さいラベル(PARCEL、灯台島まで)は 540px では読みにくい。
- シルエットだけでも主役は「板に乗った人+後ろにたなびく布+背中の箱」と分かる。SF2 では稲妻のシルエットが主役の胸の前を横切って重なる。

## 前回の初稿と比べて良くなった点(見た目の判断は利用者に任せる)
1. **主役がいる**: 画面の高さの約4〜5割の配達人。3トーン(地・月光の明・青寄りの陰)+灯り箱からの琥珀のリム。前回は約120px の記号だった。
2. **ゲームプレイの因果が1枚で読める**: SF1 は「行動(駆け上がる)+危険(稲妻)+結果(NEAR MISS +150 ×4)+HUD」。SF2 は「回り込み→ヒットストップ→PERFECT +800→STREAK ×12・LUMI 満タン」。前回は特徴の説明板(メーター・見出し・説明文)だった。
3. **奥行き**: 背景は 空/星と月/遠い雲海/遠い島/嵐/中景の雲/中景の島/気流/手前の岩とぼかした雲/光の粒 の8〜10層。遠いほど彩度を落として空の色へ(大気遠近)。前回は2〜3層の平塗り。
4. **局所光**: 灯り箱・家の窓・空板のひれ・稲妻・嵐の目が、それぞれ周りを照らす。色に意味がある(琥珀=味方、白青と紫黒=危険)。
5. **ロゴ**: 字形をパスにして、反らし・i を灯りに置換・スウッシュで下端を切り欠き・押し出しと縁の光。白黒版でも読める。スウッシュの先端に主役を乗せて、物語の終わりとつないだ。
6. **架空の表記**: 発売日・機種を書かず、「架空のゲームのコンセプト映像です。発売の予定はありません。」と明記。

## まだ弱い点・気になる点(厳しめに)
1. **ロゴは元の書体の形がまだ強い**(加工は反らし・灯り・切り欠きの3点で、字形そのものは FullmoonMarch のまま)。「独自感」が足りるかは利用者の判断。灯りの i は小さく、540px では白い点に近い。
2. **嵐の塊(SF1 左上)が「紫の岩」に見えやすい**。縁が硬く、雲らしい千切れ・薄い端がない。SF2 の渦は帯の重ねで雲らしさが出たが、帯が「触手」にも見える。
3. **キャラの作画**: 手が丸い玉で、手袋・指の形がない。胴が細長く、腰から下の比率が大きい。SF1 は板の傾きに体ごと乗っているので、体が後ろに反って見える瞬間がある。横顔の目と口は小さく、表情はほぼ無い。アニメーションで関節がどう見えるかは未確認。
4. **HUD の書体**(Vectura): 0 に斜線が入り、M・W が独特。「NEAR MISS」の単語間が広い(Canvas の wordSpacing で詰めたつもりが効いていない)。小さいラベル(22〜26px)は 540px で読めない。
5. **雲の量**: SF1 と SF3 で中景の雲海が画面の下半分を広く占め、のっぺりした灰青の面に見える所がある(こぶの明暗はあるが、形の変化が少ない)。
6. **画面の情報量**: SF2 は渦・稲妻2本・気流・白い輪・放射線・PERFECT・HUD 4か所で、見る所が多い。動画では一瞬なので許容範囲かもしれないが、静止画では騒がしい。
7. **稲妻の閃光**は静止画では強い。動画で白青の閃光が続くと光過敏の目安(1秒に3回)に触れうるので、第2段階で数える。
8. **SF3 の主張文と小さな配達人**: 配達人(0.3倍)は 540px では点に近い。主張文の字間(6px)は明朝には広い。
9. 2D の「描いた絵」の質感の上限: 筆のむらはノイズの明暗で、実際の筆致ではない(depth-and-texture.md §5 の限界どおり)。

## 汎用とゲーム専用に分けた所見
### 汎用(どのジャンルの宣伝にも効く)
- **「ずらしたシルエット」で陰と光を付ける方法**(`src/lib/paint.js` の `shade`): 形のパスを1つ書けば、光の向きにずらした差分で「陰の帯・明るい帯・逆光のリム」が自動で付く。手足・マフラー・岩・家・雲・ロゴの全部に同じ関数で効いた。平塗り対策として最も効果が大きかった(前回の弱点1・2)。スキルの `depth-and-texture.md` は球と層の部品だけで、任意の形の陰影の作り方は書かれていない。
- **色に意味を固定する**(味方=琥珀、危険=白青/紫黒、背景=藍〜青緑): 1枚で「何が良くて何が悪いか」が読める。
- **スタイルフレームを先に作る順番**: 静止画の段階で、主役の不在・ロゴの読みにくさ(スウッシュで U が II に見えた)・HUD とロゴの重なり・月と HUD の重なり・PERFECT が主役を隠す、を見つけて直せた。アニメーションの後では直しが重い。
- **効果を切った版と、シルエットだけの版を同じコードで出す**(`?fx=0`、`?sil=1`): 描画関数ごとに「効果か形か」を分けておくと、確認の版が無料で出る。
- **白黒でロゴの字形を先に確かめる**: 質感の前に読みやすさの事故(切り欠きで字が欠ける)が分かった。
- **主役をロゴの画面まで持ち越す**(スウッシュの先端に乗せる): business-motion-film の「1つの主役を通す」の具体例。
- 道具: `src/tools/glyph_paths.py`(文字→SVG パス)、`src/tools/subset_jp.py`(@fontsource の分割ファイルから必要な字だけ取り出して unicode-range 付きの CSS)、`src/tools/render_still.mjs`(HTML の canvas を PNG に。ページのエラーで止まる)。どれもジャンルを問わず使える。
### ゲーム専用
- 疑似プレイの因果(行動→反応→結果→HUD)と、数字の流れをショット表で先に固定する(距離・耐久・STREAK・ゲージ)。
- NEAR MISS / PERFECT / STREAK のような「結果の言葉」を主役のそばに出す(HUD の隅ではなく)。
- ヒットストップは静止画では「白い輪+放射線+背景の流れの停止」で表した。動画での見え方(1/2/4 コマ)は第2段階で比べる。式は BRIEF.md §7(資料の式は1コマ多く止まる)。
- motion-prompt のギャラリー(192件)には、ゲーム固有の動き(被弾の点滅・数字のポップ・HUD の2段ゲージ・ボス登場)が無い。予備動作・余韻・衝撃の揺れ・フリーズフレームは使える見込み。
