# LUMIWAKE 30秒ティザー — BRIEF(2D再試験 第2回・第1段階)

作成: 2026-10-30。前回(枝 `claude/skill-2d-trial` の `claude-video-skill/docs/2d-trial/FINDINGS.md`、15秒の初稿)と同じ題材で、30秒・effort high でやり直す。
**第1段階はここまで**: BRIEF・ショット表(`SHOTS.md`)・スタイルフレーム3枚(`frames/`)・自己点検(`REVIEW_STAGE1.md`)。アニメーション・音・書き出しは、利用者がスタイルフレームを承認してから(第2段階)。

## 1. 概要
| 項目 | 内容 |
|---|---|
| 題材 | 架空のゲーム『LUMIWAKE(ルミウェイク)』。浮遊島の夜空を、光の気流に乗って荷物(灯り)を届ける配達人のアクション |
| 遊びの核(1文) | 琥珀の「光の気流」に乗って加速し、嵐の稲妻と乱気流をぎりぎりでかわして、島へ灯りを届ける(届けると島が点灯する) |
| 主役 | 配達人ミオ。空板に乗り、背中に四角い灯り箱、長い朱のマフラー、額に飛行ゴーグル(見た目の約束は `src/lib/courier.js` の冒頭) |
| 尺・画面 | 30秒 = 900コマ、1920×1080、30fps、横 |
| 用途 | ゲームの宣伝ティザー(疑似プレイ演出のコンセプト映像)。無音で見ても分かること |
| 表記 | 「架空のゲームのコンセプト映像です。発売の予定はありません。」を最後の画面に出す。発売日・価格・ストア名・機種は書かない |
| 禁止 | 人物写真、AI 生成のフラット PNG の貼り合わせ、3D、実在の作品・商標に似せること、既製フォントそのままのロゴ |

## 2. 30秒の構成(調査の一致点を前提にする)
前提: 冒頭0〜3秒に「行動+危険+結果」を同時に見せる/スタジオロゴは冒頭に置かない/情景カットは2枚まで/説明の板は作らず、行動→反応→結果→HUD の数字の因果で見せる/主張は2つまで/ロゴと架空表記は最後の1枚/15秒の引き延ばしにせず「失敗・再挑戦・報酬」を足す。

| 区間 | 秒 | 役割 | 中身 |
|---|---|---|---|
| フック | 0–3 | 行動+危険+結果 | 気流を駆け上がる配達人の真後ろに稲妻。かわして NEAR MISS +150(スタイルフレーム1) |
| 情景1 | 3–6 | 目的地 | 灯りの消えた島の町を見下ろす。主張1「嵐を抜けて、灯りを届けろ。」 |
| ルール | 6–10 | 操作と因果 | 気流から気流へ跳び移る → 光の粒を拾う → LUMI ゲージが満ちる → 加速 |
| 失敗 | 10–14 | 危険が本物だと分かる | 嵐の腕が荷物をかすめる → 画面が揺れる → PARCEL 3→2(割れた灯り)→ 体勢を崩す |
| 再挑戦・見せ場 | 14–20 | 遊びの応用 | 立て直して嵐の目を回り込む。完璧なタイミングでヒットストップ、PERFECT +800、STREAK ×12(スタイルフレーム2) |
| 報酬 | 20–24 | クライマックス | 灯台島に届ける → 灯台が点灯 → 町の灯りが波のように広がる |
| 情景2 | 24–26 | 余韻 | 引きの画。灯った島々が航路の光でつながる。主張2「届けた灯りが、空の道になる。」 |
| ロゴ | 26–30 | 名前を覚える | 航路の光がスウッシュになりロゴ着地、静止保持、架空の表記(スタイルフレーム3) |

主張は2つだけ: ①嵐をかわして届けるアクション ②届けると世界(夜空の地図)が変わる。特徴の箇条書き(協力プレイ等)は出さない。

## 3. 調査の要点と前回の弱点の対応表

## 6. 書体とライセンス
- ゆうたONE パック(英字のみ): ロゴ=Y1FullmoonMarch、HUD=Y1Vectura。利用者がフォロー済みで商用条件を満たす(利用者の申告)。**フォントファイルはリポジトリに入れない**(`assets/fonts/` は .gitignore)。ロゴは字形をパスにして加工した物(`src/lib/logo-glyphs.js` は8字の輪郭データ。フォントファイルではない)。原型を保ったロゴの商標登録はしない。
- 和文: Zen Old Mincho、Noto Sans JP(どちらも SIL OFL 1.1、`@fontsource` の npm パッケージ 5.3.1 から取得)。`src/jp_text.txt` の字だけにサブセット化(`src/tools/subset_jp.py`)。サブセットもリポジトリには入れず、`src/tools/setup_fonts.sh` で作り直す。

## 7. 第2段階への申し送り(まだ実装しない)
- 枠組み: HyperFrames(SKILL.md §2)。`<canvas>` 1枚に、止めたタイムラインの時刻から `src/lib/*.js` で描く。スタイルフレームの関数はすでに時刻 t の純関数(乱数は seed 付き、同じ引数で同じ画素になることを2回描いて md5 一致で確認)。
- 動き(motion-prompt のギャラリー、`search` で見つけた候補。`get` はまだ): #121 予備動作(S3 の跳び移り)、#122 余韻(マフラーの揺れ戻り)、#011 つぶしと伸ばし(着地)、#024 衝撃の揺れ(S4 の被弾・S8 のロゴ着地)、#040 フリーズフレーム(ヒットストップの考え方)、#108 流し撮り(S1 の背景の流れ)、#035 FPV(S5 の周回)、#022 光の帯(ロゴ)。ゲーム固有の動き(被弾の点滅、数字のポップ、HUD の2段ゲージ)はギャラリーに無いので自作になる見込み。
- ヒットストップの式: 資料の型 `f<h ? f : f<h+n ? h : f-n` は n=2 のとき 92,93,94 の3コマが止まる(手元で計算して確認)。止めるコマ数を n にするなら `f<h ? f : f<h+n ? h : f-n+1`(この場合、以降の動きは n−1 コマ遅れる)。1/2/4 コマを比べて決める [試験値]。
- 音の山は4つ(1.6s 稲妻、11.0s 被弾、17.4s PERFECT、27.0s ロゴ)。BGM は1曲として切らない(SKILL.md §4b)。
