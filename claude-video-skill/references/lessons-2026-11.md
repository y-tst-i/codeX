# 2026-11 の試験の教訓(運用・音・MV・人型・Windows)

LUMIWAKE(2D ゲームティザー 30秒)と MV『夜明けの回路』(2D タイポグラフィ MV 53秒)の試験で分かったこと。**どれも1回・1人の判定か、1回の実測**で、確定ではない。事実と推測を分けて書く。

## 1. 担当の起動と運用(確認済みの事実)
- **通しの映像制作は Opus 5.5 / high を前提にする。** 同じ設計・同じ音で、実装担当だけを Sonnet 5.5 / medium と Opus 5.5 / high に変えて名前を伏せて比較(LUMIWAKE 30秒、2026-11-09)→ 利用者は Opus / high を「絶対」と選んだ。過去の比較とも同じ向き: Opus と Sonnet(15秒見本の2場面)は2場面とも Opus、medium と high(STILLDUSK 4場面)は high 2・medium 1・差なし1。**モデルと effort を同時に変えた比較なので、どちらが効いたかは分けられない**(分けるなら「Opus / medium」「Sonnet / high」を作る)。medium で作ってから high で作り直すより、最初から high のほうが安い(試した利用者の判断)。
- **起動時に `model` と `effort` を明示し、起動直後に記録で確かめる。** 記録は `tasks/<id>.output`(JSON行)で、`grep -o '"model":"[^"]*"'` と `grep -o '"effort":"[^"]*"'` で数える。
- **止めた担当を SendMessage で再開すると、設定が親(Sonnet 5.5 / medium)に変わることがある。** LUMIWAKE の第2段階は、2026-11-02 の再開以後、286件すべてが Sonnet 5.5 / medium だった(利用者には「high」と伝えてしまっていた)。一方、MV の再開(2026-11-10、枠の制限後)は Opus / high のままだった(244件)。→ **再開のたびに記録で確かめ、変わっていたら止めて、モデルを明示した新しい担当を起動する。** 長い作業は区間ごとに新しい担当を起動し、ディスクの成果物(コミット済みのソース、書き出した区間)から続ける。
- **環境が作り直されると、作業用フォルダ(scratchpad)・アップロードしたファイル・入れたスキル(`~/.claude/skills`)が消える。** 担当を起動する前に、指示に書いたパスとスキルが実在するか確かめる(2026-11-09 に消えていた: 第三者の調査資料、2D 調査の要約、`video-with-claude-code`)。必要なものはリポジトリのブランチにコミットしておく。
- **利用枠(5時間)で止まる**: 長い書き出しは5秒ずつの区間に分け、区切りごとにコミット&push。リセット後に再開メッセージを送る(上の確認つき)。

## 2. 進め方(2D・MV)
- **静止画(スタイルフレーム)3〜4枚を先に作り、利用者が承認してからアニメーションに進む。** 絵の安っぽさ・主役不在・文字の欠けを、静止画の段階で直せた。
- **音ハメ = 実測のアクセント台帳 + 機械検査**(許容 ±1 コマ)。拍の格子は仮定せず、曲から測ったアクセント時刻(STFT のスペクトル変化のピーク)を使う。LUMIWAKE は映像のヒット22〜28件が ±1 コマ以内。ただし台帳に合わせて作った結果なので、独立の証明ではない。
- **ボーカル曲の歌詞の時刻**: faster-whisper(small、CPU、日本語)の語の時刻は、歌声だと誤認識が多く、使えるのは各行の始まりと終わりの目安だけ。旋律の高さの地図・音量の谷と照合して裏取りし、確信のない所は「要確認」にして、**確認用の下書き動画(黒地に歌詞が時刻通りに出るだけ)を利用者の耳で確かめる**のが最も安い。歌詞の時刻は JSON のデータにして、コードに直書きしない(直しが区間の再書き出しだけで済む)。道具(ブランチ `claude/mv-yoake-no-kairo` の `examples/mv-yoake/src/tools/`: vocal_probe、vocal_isolate、pitch_map、whisper_check、lyric_check_video、cue_check)。
- 描画の不具合(両試験で共通に見つかった): 作業 canvas の状態が前のコマから残る(毎コマ初期化する)/分割した日本語フォントが初めて出る文字で遅延読み込みになり、並列書き出しの最初のコマだけ字が変わる(使う全文字を先に読み込む)/`fromTo` に `immediateRender:false` を付けると開始前のコマで要素が見える(付けない)/ヒットストップの式 `frame<hit+fr ? hit : frame-fr` は1コマ多く止まる(`frame>=hit+fr ? frame-fr+1`)。

## 3. 人型キャラ
- **コードで描く人型キャラは、モーショングラフィック全体の質を下げる**(利用者判定。骨格・顔・手・しわのどれかが崩れると安っぽく読まれる)。主役は非人型(光・図形・文字)にする。LUMIWAKE の灯りの精は許容された。人型が必要な作品は、別の方法(ブレンダーのトゥーン描画の素材、利用者が用意した絵)で作る。
- ブレンダーはクラウドでも `pip install bpy==4.5.14`(Python 3.11)で画面なしに動く(球を作って GLB 書き出しまで確認。複雑なモデルの品質は未確認)。利用者の PC(CL716)にも 4.5.14 LTS が入っている。

## 4. 音
- **コードで作った効果音は、本物の曲(Suno)と並ぶと「浮く」**(利用者判定、LUMIWAKE)。合成の鈴や低音は質感が安い。
- **Audio Studio の効果音モデル(`sm-sfx`)の出力は、そのままでは使えないことがある**: 稲妻は音のほぼ全部が上限で割れていた(77%)、鈴は打撃の約0.45秒前に助走があり打撃周辺が割れていた、「低い灯りの音」は100%が120Hz以下(小さなスピーカーではほぼ聞こえない)。**測ってから、助走を切る・減衰の形に整える・倍音を足す・音量を曲の帯域に合わせる**。試作ミックスの道具: `tools/mix_sfx_over_song.py`(位置は「打撃の頂点 = 絵のコマの1コマ後」。測定で位置が合うことを確認済み。聴いた判断ではない)。
- **Suno**: Web 版で手作業で作れる(Custom モード: 歌詞の欄とスタイルの欄)。公式 MCP(ベータ、`https://api.suno.com/mcp`)は公式FAQで「無料プランを含む全プランで使える」とあるが、接続は OAuth のサインインが要り、利用者の環境では原因不明のエラーで接続できなかった(サーバー側の公開設定は正常に見えた)。**無料プランの曲は個人・非商用で、Suno への表記が条件と報告されている(第三者の解説。公開前に利用規約で確認)**。曲は3分前後と長いので、構成(音量の流れ)を測って、30〜60秒の区間を切り出す。歌詞は Claude がオリジナルで書ける(借り物を使わない)。
- 曲の測定は `ffmpeg ebur128`、構成は1〜2秒ごとの音量、アクセントはスペクトル変化のピーク。AI は音を聴けないので、聴いて確かめてほしい点を報告に書く。

## 4b. 未解決: 絵が「ポリゴンくさい」
- MV 初稿(2026-11-10)に対する利用者の感想: タイポの演出は良いが、**絵がまだかなり「ポリゴンくさい」**(コードの図形・グラデーションの質感)。「Xなどに上がっている人たちの動画のほうが質が高い」とも言われている。
- 試す候補(どれも未検証): ①質感素材を実写・画像生成(Codex)で作って2Dに合成(以前、フラットな画像の貼り合わせは不評だったので、質感の素材に限る)②ブレンダーのトゥーン/ペイント風の描画を素材にする ③CC0 の質感テクスチャ・ブラシで手描き風にする ④three.js の3Dで奥行き(3Dの試験は質が出たが、書き出しが重い)。

## 5. ローカルPC(CL716、Windows)
- 調査結果(2026-11-04): Ryzen 5 PRO 215、内蔵 Radeon 740M(独立GPUなし)、メモリ約15GB(空き約1.7GB)、Node 24、ffmpeg 9、git 2.56、Blender 4.5.14、Python は PATH に無い(Audio Studio の専用 venv とブレンダー同梱がある)、fluidsynth は無かった(作業フォルダに展開して使える)。書き出しは、同じ雛形(1080p・90コマ)で、ローカル約0.15〜0.19秒/コマ、クラウド約0.06〜0.08秒/コマ(クラウドが約2倍速い)。2D の Canvas 作品はローカルでも約0.07〜0.08秒/コマで十分。→ 書き出しを理由にした移行はしない。PC の道具(Audio Studio、ブレンダー、Suno)を使うために、ローカルの Claude を使う。
- Windows(Git Bash)で動くようにしたスクリプト修正はブランチ `claude/skill-windows-compat`(未マージ。実機での確認が必要な点は `references/windows-setup.md`)。
