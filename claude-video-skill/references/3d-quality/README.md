# 3D の品質基準 — 初稿から安っぽく見せないために

three.js の3Dを**初稿から**高い品質で出すための決まり。作り方(ひな形・パス・seek の約束)は `../three-3d.md`。ここは「出す前に何を確かめるか」と「何を比べて決めるか」。
技術ごとの数値と失敗は `techniques.md`(12技術。1節ずつ読む)。数値・ライセンスをどこで確かめたかは `sources.md`。

表記: **【検証済み】**= 一次情報(公式のソース・docs・README・LICENSE)で確かめた、またはこのリポジトリで実測した。**【検証済み(環境: …)】**= 試験で実際に効いた(どの環境の何作目かを書く)。**【未検証】**= 外部の調査(ChatGPT・Grok)の候補や推測。試験値として扱い、正解とは書かない。

試験の記録: 実例1「水晶の空」(§4)、実例2「断崖の灯台と夕景の海」(§4b。別の題材で、この基準だけを頼りに初稿を作った試験)。

## 1. 初稿を出す前の必須ルール

| # | ルール | 何を見るか・どうするか |
|---|---|---|
| 1 | **主役の物は滑らかな面+分割数の下限** | 主役(画面の 1/4 以上に映る島・岩・地形)は `flatShading` を使わない。頂点を共有する(インデックス付きの)形にして `computeVertexNormals()`。three の `IcosahedronGeometry` などの多面体は**インデックスなし**で作られるので、そのままでは法線が面ごとになる【検証済み】(r181 `PolyhedronGeometry.js`「build non-indexed geometry」、`BufferGeometry.computeVertexNormals()` の非インデックス分岐)。三角形の目安は §4 の実例(近景 13万〜18万、中景 3万〜8万、遠景 4,500)【検証済み・実測。1作品】。**崖(縦の壁)は高さの地図では作れない**: 高さ場 128×128+flatShading(案A)は壁が縦長の三角形の扇になり、2倍拡大しなくても面の割れが見えた。海岸線に沿った格子 `P(s,y) = C(s) + N(s)·D(s,y) + 上·y`(C=海岸線、N=海側の向き、D=張り出し量)にすると、約100単位の距離・2倍拡大で面の割れは見えなかった(崖 約42万三角形、列 1000(岬の周り ±75 を約5倍密に)× 行 210)【検証済み(環境: クラウドのコンテナ・SwiftShader(software gpu・4コア)・three r181・HyperFrames CLI 0.8.220・1920×1080・30fps。実例2)】 |
| 2 | **近景で拡大して確かめる** | 主役が一番大きく映るコマを、2倍に拡大して見る(輪郭がカクカクしないか、陰影が面ごとに割れないか)。全体の縮小コンタクトシートだけでは低ポリに気づけない(水晶の空の初稿はこれで見落とした) |
| 3 | **全コマの黒・NaN 検査** | `python3 tools/review_checks.py <mp4>` の黒コマ。加えて、画面の一部や1コマだけ真っ黒になる NaN/Inf に注意(Bloom があると1画素の NaN が画面全体に広がる)。ポストの最初で NaN/Inf を 0 にする(水晶の空の `post.js` で実施)【検証済み・実測】。**注意: スキルの `tools/assets/three/post.js` にはこの処理が入っていない**(2026-10-30 確認)。作品にコピーした `assets/post.js` の CoC のシェーダーで色を読んだ直後に `if (any(isnan(col)) \|\| any(isinf(col))) col = vec3(0.);` を足し、最初のパスの後に同じ処理の ShaderPass を1枚足す(実例2で実施。120コマで黒い画素 0)。mp4 では NaN そのものは測れないので、各コマの「ほぼ黒(RGB の最大 < 8)の画素数」と全面の黒コマで見る |
| 4 | **変更の前後を同じ時刻で比べる** | 直す前と後を、同じ時刻・同じカメラ・同じ光で撮って横に並べる(`§3` の手順)。改善した理由を1行で書けるようにする。1回に変える要素は1つ(形だけ/材質だけ/光だけ) |
| 5 | **Bloom・雲・DOF を切った比較** | 同じ時刻を「全部あり」「Bloom なし」「雲なし」「DOF なし」で撮る。切ると主役の形が読めなくなるなら、効果でごまかしている。光る物は Bloom なしでも模様が読めること。**差を数値でも見る**(同じ時刻の画素の差: 差が10を超える画素の割合)。実例2では Bloom を切った差が 0.02% しかなく、「Bloom で光らせたつもり」が画面では効いていないと分かった(小さな灯の emissive 7・threshold 1.6)。雲なし 1.78%、DOF なし 0.10%【検証済み(環境: クラウドのコンテナ・SwiftShader(software gpu・4コア)・three r181・HyperFrames CLI 0.8.220・1920×1080・30fps。実例2)】 |
| 6 | **決定性(順・逆・飛ばし seek の一致)** | 同じ時刻を、順に・逆順に・飛ばして seek して撮った画像が一致すること(§3 の手順 5)。HyperFrames 0.8.220 のソースでは、**直前と同じ時刻の seek では `hf-seek` が再送されない**(重複を省く仕組み)【検証済み】ので、同じ時刻を2回撮るときは間に別の時刻を挟む。`snapshot --at 0.5,1.5,2.5`(順)と `--at 2.5,1.5,0.5`(逆)と `--at 2.5,0.5,3.9`(飛ばし)で、同じ時刻の PNG が全画素一致した。`--workers 1` と `2` の書き出しも framemd5 が120コマ全部一致【検証済み(環境: クラウドのコンテナ・SwiftShader(software gpu・4コア)・three r181・HyperFrames CLI 0.8.220・1920×1080・30fps。実例2)】 |
| 7 | **出典値と試験値を分ける** | 指示書・コメントに数値を書くとき、公式の既定値・サンプル値(出典値)と、自分で決めた試験値を区別する。外部の調査の「推奨値」はその作品の設定であって正解ではない |
| 8 | **ライセンス台帳** | 使う外部のコード・素材ごとに「URL・作者・ライセンス・確認日・改変・クレジット義務・置き場所」を1行で残す(§5)。**LICENSE ファイルの無いリポジトリのコードは写さない**(参考に読むだけ) |
| 9 | **公式サンプルをそのまま貼らない** | three の公式サンプルは実時間で動く(`performance.now()`、毎フレーム `frame++`)。HyperFrames では t とコマ番号に置き換える【検証済み】(`webgl_shaders_ocean.html` 200行目、`webgl_volume_cloud.html` 305・307行目) |
| 10 | **WebGPU 専用の物を混ぜない** | この環境(ソフトウェアGL)では WebGPU が動かない(`../three-3d.md` §8)。`webgpu_*` のサンプル、TSL、`WebGPURenderer` 前提のスキル・作例は使えない |

## 2. 依頼文に足す1段落(コピーして使う)

> 主役の物(島・岩・地形・建物)は flatShading を使わず、崖のような縦の壁は高さの地図ではなく海岸線に沿った格子(位置 = 海岸線 + 海側の向き×張り出し量 + 上×高さ)で作り、頂点を共有した形で computeVertexNormals する。主役の分割は近景で10万三角形以上を目安にし、分割を減らすのは遠景だけ。形は大きな形+中くらい(崖のすじ・地層)+細かい凹凸の少なくとも3段のノイズで作る。単色の面を作らない(高さ・傾き・ノイズで色を変える)。Bloom・DOF・雲を切っても主役の形と模様が読めること。公式サンプルの performance.now() と frame++ は t とコマ番号に置き換える。太陽はカメラから見える主役の面に斜めに当たる向きにする(真後ろからの逆光だと面が1色に見える)。地層の縞は厚さをばらつかせ、色の差を平均色へ半分ほど寄せる(等間隔のはっきりした縞は「ケーキの断面」に見える)。出す前に、主役が一番大きく映るコマを2倍に拡大した画像を自分で見て、輪郭の角と面の割れが無いことを報告する。

## 3. 初稿前の「小さな比較試験」(2〜3秒のカットで A/B/C)

全編(20秒・600コマ・ソフトウェアGLで約1時間)を作る前に、**一番大事な2〜3秒のカット**だけで案を比べて決める。

1. **案を決める**: 変える要素は1つだけ。例: A = 今の島、B = 高分割+多重ノイズ+滑らかな面、C = B+崖の張り出し(SDF)。形の比較なら光・カメラ・材質は同じにする。
2. **同条件で作る**: 作業フォルダを案ごとにコピーし(`proj_A/ proj_B/ proj_C/`)、違いは先頭の定数1か所だけにする。カメラ・光・乱数の種・時刻は同じ。場面のコードは `scene.js` に出し、`index.html` の設定(`const CFG = { VARIANT: "B", BLOOM: true, … }`)だけを案ごとに変えると、比べる物の取り違えが起きにくい(コードを直したら全部のフォルダにコピーし直す)。効果を切った比較(ルール5)も同じやり方でフォルダを作る。
3. **同じ時刻で撮る**: `npx hyperframes snapshot --at 0.5,1.5,2.5 --no-end --timeout 120000`(各フォルダで。`-o <フォルダ>` で置き場所を固定すると比べやすい)。**snapshot はページの JS の例外を出力に出さない**(実例2で、定義し忘れた関数があっても出力は「saved」だけだった)→ 撮った画像を必ず開いて見る。カットの切れ目があれば、切れ目の直前と直後のコマも(HyperFrames の公式アダプター資料 `hyperframes-animation/adapters/three.md` の式: 直前 = `(ceil(cut*fps)-1)/fps`)【検証済み】。
4. **並べて見る**: 同じ時刻の A/B/C を横に並べた1枚を作る(`ffmpeg -i A.png -i B.png -i C.png -filter_complex hstack=3 cmp.png`)。主役の部分を2倍に拡大した版も作る(`crop` → `scale`)。効果を切った版(ルール5)もここで撮る。
5. **決定性**: 選んだ案で、2〜3秒を `--workers 1` と `--workers 2` で書き出し、`ffmpeg -i X.mp4 -f framemd5 -` の一致を見る(この方法で全コマ一致した実績: `../three-3d.md` §8)【検証済み・実測】。`snapshot --at` に逆順(`2.5,1.5,0.5`)・飛ばし(`2.5,0.5,3.9`)を渡すと、渡した順にファイル名が付き(frame-00-at-2.5s …)、順に撮った物と全画素一致した【検証済み(実例2)】。同じ時刻の重複を渡す場合は試していない。
6. **時間を測る**: 1コマあたりの書き出し時間を記録し、600コマの見込みを出す(水晶の空 v2: 約6秒/コマ。実例2: 約4.7秒/コマ(120コマ 9分27秒)。`--workers 2` は 8分56秒でほぼ同じ)。3時刻の snapshot は1案あたり約30〜60秒(ページの読み込みと形の生成を含む)なので、比較試験は全部で数分で済む。
7. **決めて記録する**: 選んだ案・理由(1行)・数値(三角形数・ms/コマ)・比較画像の置き場所を残す。ここで決めてから全編を作る。

利用者に見せるのは、比較画像1枚と「どれにしたか・なぜか」の1行。

## 4. 実例: 「水晶の空」の初稿が低ポリに見えた(2026-10-30)

20秒の3D映像(浮遊島・水晶・雲海・魔法陣)。枝 `claude/crystal-sky` の `claude-video-skill/examples/crystal-sky/`(`proj/index.html` の `islandGeo()` 周辺、`README.md` の「v2: 島の作り直し」)。

| | v1(初稿。指摘「空・雲は良いが、島が低ポリ感」) | v2(解消) |
|---|---|---|
| 面 | `flatShading: true`。しかも `IcosahedronGeometry` はインデックスなしなので、法線が面ごと | flatShading なし。同じ位置の頂点をまとめてインデックス付きにし、`computeVertexNormals()` |
| 分割 | `IcosahedronGeometry(1, 5)` = 20×6² = **720 三角形/島**(全部の島が同じ) | 距離で変える。近景 detail 80〜96 = **131,220〜188,180**、中景 detail 40〜64 = **33,620〜84,500**、遠景 detail 14 = **4,500**(三角形数 = 20×(detail+1)²) |
| ノイズ | 低い周波数の fBm(3段: 重み 0.6/0.3/0.1、周波数 ×1/×2.1/×4.3)だけ | 大きな形は同じ式のまま、地層の段(1.7 単位ごと)・縦の崖のすじ(リッジ)・割れ目・細かい凹凸・底の垂れ下がる岩を頂点と色に足した |
| 上面・ふち | 単色に近い | 草の濃淡・土・岩の出っ張り・草のふち(縁から垂れる草)、側面の上に苔と土、底から根(先が細くなる管) |
| 木 | 円すい1個(flatShading) | 幹+丸い葉の房6つ(下が濃く上が明るい、1本ずつ色を変える)を InstancedMesh で。高さは島の上面に合わせる |
| 細部のシェーダー | なし | 微細なノイズで法線と色を揺らす(画素より細かくなる遠景では弱める) |
| 書き出し | 48分12秒/600コマ | 59分50秒(約 +24%) |

**教訓**: ①多面体の形は「flatShading を外す」だけでは滑らかにならない(頂点を共有させる)。②分割を一律に増やすのではなく、近景だけ上げる(遠景は 4,500 で足りた)。③大きな形を変えずに細部の層を足せば、カメラ・構図・魔法陣の見え方を保ったまま直せる(祭壇の真下は v1 と同じ高さ、乱数の並びも同じにした)。④この失敗は数値の検査では出ない。ルール2(近景の拡大)で見る。

## 4b. 実例2: 「断崖の灯台と夕景の海」(2026-10-30、この基準の試験)

4秒・1920×1080・30fps、three.js、人物・音なし。この README と `techniques.md` と `../three-3d.md` だけを頼りに初稿を作り、崖だけを変えた A/B/C を同条件で比べた(作業ファイルはリポジトリ外。mp4 も入れていない)。

| 案 | 作り | 三角形(崖) | 3時刻の snapshot | 結果(人が見て判断する前提の、作り手の所見) |
|---|---|---|---|---|
| A | 高さ場 128×128 + flatShading + 単色 | 約3.3万 | 31秒 | 壁が縦長の三角形の扇。面ごとの割れが縮小画像でも見える。単色 |
| B | 海岸線に沿った格子(インデックス付き・`computeVertexNormals`)、D = 入り江のゆらぎ+海中の裾+波の刻み+上部の張り出し+地層(厚さ 1.2〜2.6 にばらつき)+縦のうね+縦の溝+fBm 4段(lacunarity 2・gain 0.5)+細かい凹凸。色は地層・縦の筋・濡れ・棚の草・上端の土。台地は別の高さ場 | 約42万 | 36秒 | 2倍拡大で面の割れなし。**採用** |
| C | 符号付き距離(陸までの距離+D)を 0.5 単位の格子で surface nets。岬の周りの箱だけ C、外は B | 箱の中だけ | 58秒 | 彫りは B より深く見えるが、箱の境目で崖が切れて見え、箱の外の水面に縦の筋が出た。直さずに見送り |

**効いたこと**: ①ルール1(滑らかな面+分割の下限)と、縦の壁を海岸線の格子で作ること(A→B の差が最も大きい)②ルール2(2倍拡大)③ルール5を数値で見ること(Bloom が効いていないと分かった)④ルール6(順・逆・飛ばし、workers 1/2 で一致)⑤ルール10(WebGPU の物を使わない。公式 `Water` は WebGL で動いた)。
**基準に無くて、試して分かったこと**: ①最初の B は太陽を奥(逆光)に置いたため、見える面が影で1色に近かった。太陽をカメラの左手前寄り(方位 −68°・高度 7°)に変えると縦の溝と地層が読めた ②等間隔で色の差が大きい地層は「ケーキの断面」のように見えた → 厚さのばらつきと、平均色へ 45% 寄せる ③海は `distortionScale 3.7`・`size 1.6`(サンプルの値)だと湖のような鏡面に見えた → 6・4.0 で波の細かさが出た(反射 1024²)。それでも崖の映り込みは強く、外洋らしさは人が見て判断してほしい ④灯の光の筋(加算の円すい)は、最初の強さ(0.09)では夕景の空に負けて見えなかった → 0.36 で見えた。

**まだ気になる点(作り手の目視。人が見て判断する前提)**: 崖の面がやや粘土のように柔らかく、岩の硬い割れ目が少ない/影になる奥の崖は単色に近い/遠くの台地が平らで、地平線の陸の輪郭にジャギー(MSAA なしの `fast`)/水面の映り込みが強く湖っぽい/草は縁で房の形が見えるが、台地の中は点の模様/白飛びの画素は 0(灯も飛んでいない=光の強さの演出としては弱い)。

## 5. ライセンス台帳の書式

作品フォルダの `README.md` か `CREDITS.md` に表で残す(水晶の空の README の「素材とライセンス」と同じ形)。

| 素材・コード | URL | 作者 | ライセンス | 確認日 | 改変 | クレジット義務 | 置き場所 |
|---|---|---|---|---|---|---|---|

- コードのライセンスと、同梱の素材(モデル・テクスチャ・フォント)のライセンスは別物。glTF サンプル集のようにモデルごとに違う物もある。
- 再配布が禁止の素材(例: Quaternius の QAL)は公開リポジトリに入れず、取得手順だけ書く(`../three-3d.md` §7)。
- 主なリポジトリ・素材の確認結果は `sources.md` §3。
