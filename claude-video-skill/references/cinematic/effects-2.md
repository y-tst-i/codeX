# 撮影・光学効果(後半)(29技法)
> 出典: melies.co/cinematic-techniques(要約・再構成。原文の転載ではない)。HyperFramesでの実装レシピは本スキル独自。

## このグループの選び方ガイド
- **光の事故を作りたい**: 光源に追従する散乱 → レンズフレア / 全画面が一瞬白く飛ぶ(編集の継ぎ目になる) → ライトフラッシュ / 画面の縁から汚れが入る(カメラ側の故障) → ライトリーク / 四隅が暗く落ちる → ビネット。見分け方は「原因がどこにあるか」(光源・露光・フィルム縁・レンズ周辺)。
- **見る装置を作りたい**: 覗き穴の形で切る → マスキング / 暗視ゴーグル(緑・粒子・ブルーム) → ナイトビジョン / 熱を色にする → サーマル / 透過して構造を見せる → X線。この3つの擬似視覚は「色補正ではなく装置」として作る。
- **変化を見せたい**: 輪郭の対応点が動く → モーフ/モーフィング / 世界や状態が入れ替わる → トランスフォーメーション / 物が別空間への穴になる → オブジェクトポータル / 貼り物が剥がれて下が出る → ステッカーピール。
- **焦点・枠・時間をいじりたい**: ピント移動 → ラックフォーカス / 薄い被写界深度 → シャローフォーカス / 枠そのものが広がる → アスペクト比切替 / 2視点の揺れ → ウィグルグラム / 回転を静止ポーズの輪に → ゾートロープ / 時間を軸方向に引き伸ばす → スリットスキャン。
- **画面の素材感**: 数えられる粒 → パーティクル / 文字が空間にいる → タイポグラフィ / 異種メディアの衝突 → ミックストメディア / 黒い切り絵の層 → シャドウボックス / スキャンした実景 → フォトグラメトリ / 面に映像を載せる → プロジェクション。
- 入門でまず覚える3つ: **ライトフラッシュ**(最小コストで切替が効く)、**ビネット**(1行で画が締まる)、**ラックフォーカス**(視線を動かす基本)。
- 実写・AI生成前提でコード再現が難しいもの(代替案つき): レビテーション(ワイヤー消し)、スケールシフト、セルフィーツイン、フォトグラメトリ、スマッシュアンドグラブ、フロントプロジェクション等。

## 技法一覧(エントリ)

### レンズフレア / Lens Flare  (`effects/lens-flare`)
- **一言**: 強い光源の近くでレンズ内の反射・散乱が起き、ゴースト・筋・コントラストの白濁として画面に現れる現象を、光源に紐づけて見せる。
- **物語での役割**: カメラが光を処理しきれず苦戦している感覚、つまり観客が光に圧倒される体験を与える。扉の向こうの日光、ヘッドライト、未知の光との遭遇など。
- **使う/使わない**: 格納庫の扉が開いて日光が差し込み、体が光を遮ると収まる、といった「光源が説明できる」場面で1回。光源の無い夜の室内に虹色の筋を載せない(光を遮っても変化しないなら、ただのステッカー)。
- **よくある失敗**: 光源と無関係に固定位置で漂うフレアパック。光源が動いても遮られても反応しないので偽物と分かる。
- **似た技法との違い**: アナモフィックフレアは横一本の筋に特化。ハレーションはフィルム乳剤上のにじみ。ライトリークはレンズを通らず縁から入る光。
- **HyperFramesでの作り方**: 光源位置 p(t) を1つの関数で定義し、全要素をそこから導出する。①光源: 小さな白い radial-gradient(半径40〜80px)。②ゴースト: 画面中心 c に対し c+(c−p)·k(k=0.4/0.8/1.3/1.9)に半径20〜90pxの円/六角形(clip-path: polygon)、opacity 0.1〜0.35、`mix-blend-mode: screen`、色は淡い青〜オレンジ。③白濁: 光源中心の巨大 radial-gradient を全画面に、強度 = base·(1−occ)。occ(遮蔽率 0〜1)は proxy tween(0.6〜1.0秒、power2.inOut)で動かし、被写体が光を遮る瞬間に同期させる。④横筋は既製 `npx hyperframes add vfx-anamorphic-flare`(青紫の水平ストリーク)。位置は必ず t の関数で再描画し、Math.random は使わない。
- **音との合わせ方**: 光が強まる間は高域のうなりを足し、遮蔽で一気に落とすと「目がくらむ」感覚が出る。
- **難易度/適性**: ★★(光源・遮蔽・ゴーストの連動設計が要る)。
- **AI動画生成プロンプト**: `Lens flare across [Subject], sun or hard practical striking the front element, veiling contrast, ghost orbs tracking the source, source-linked not floating.`

### レビテーション / Levitation  (`effects/levitation`)
- **一言**: 人や物がワイヤー等の支えを見せずに静かに宙に浮き続ける。足元の隙間が証拠になる。
- **物語での役割**: 重さが任意になった瞬間を、人間らしい演技のまま見せる。離陸・頂点・着地という「動作の文法」で信じさせる。
- **使う/使わない**: 人が部屋や屋上で宙に留まること自体が事実となる1カットに使う。落下(重力が主題)には使わない。ゆっくり落ちるだけならフローティングフォールの領域。
- **よくある失敗**: 風船のように漂うだけで離陸も着地も無い。布や髪が水中のように浮く(重力で下に垂れるべき)。
- **似た技法との違い**: フォーリングは重さを持って落ちる。バレットタイムは凍結した瞬間を周回する。レビテーションは生きた演技のまま持続して浮く。
- **HyperFramesでの作り方**: 実写のワイヤー消しは不向き(クリーンプレートの合成は動画編集ソフトの領分)。代替はベクターの人物シルエット/イラストで作る。①SVGの人物を y 方向に動かす。離陸は予備動作(−2〜3%沈む、0.25秒)→上昇 power2.out 0.7秒→頂点で微小ボブ(振幅4〜8px、周期3秒をsin(t)の関数で。`repeat:-1`は禁止)。②床の接地影を楕円で描き、浮上量 h に応じて scaleX 1→0.6、opacity 0.5→0.2、`blur(4→14px)`。この「影との隙間」が浮遊の説得力の本体。③衣服・髪は下向きに垂れる別パスにして、人物の動きに0.1〜0.2秒遅らせて追従(慣性)。④着地は影が戻る瞬間に小さく沈む(scaleY 0.97)。
- **音との合わせ方**: 離陸の瞬間に低音を1つ、浮遊中は音を薄くして空気の静けさを出す。
- **難易度/適性**: ★★(ベクター代替)。実写のワイヤー除去は不向き。
- **AI動画生成プロンプト**: `Levitation of [Subject], body refusing gravity, a quiet impossible hover, hair and cloth hanging downward, visible gap under the feet, no visible support.`

### ライトフラッシュ / Light Flash  (`effects/light-flash`)
- **一言**: 数フレームだけ画面を白(またはほぼ白)に飛ばして元に戻す、時間的な露光イベント。ピークでカットを隠せる。
- **物語での役割**: 記憶の刺し込み、爆発、カメラのフラッシュ、意識の飛びなど「痛い継ぎ目」を作る。白そのものが編集点になる。
- **使う/使わない**: 記憶が一閃して次のカットに沈む場面、爆発直後のカットに。画面に居座るレンズフレアや、白飛びなしの単なるハードカットには使わない。何度も使うと軽くなる。
- **よくある失敗**: 白に到達せず虹色の筋だけが残る/白の後に装飾的な筋を残す。フラッシュのピークでカット先に差し替え忘れ。
- **似た技法との違い**: スマッシュカットは白を必須としない急な編集。レンズフレアは光源が写る間残る散乱。フェードは遅い章区切り。
- **HyperFramesでの作り方**: 全画面の白div(色は `#fff` か暖色寄り `#fff4e0`)を1枚。opacity を 0→1(2〜3フレーム=約0.08秒、linear)→ピークで1〜2フレーム保持→1→0 を power2.out で0.3〜0.5秒。**ピーク時刻に tl.set でシーンA→Bを差し替える**(.clip自体にvisibilityをtweenせず、子要素で切替)。余韻の白濁は `filter: brightness(1.0→1.6→1.0)` を下の層に同期して足すと露光が飛んだ感じが出る。既製: `npx hyperframes add editorial-flash-overlay`(カメラフラッシュ風の光層)、`npx hyperframes add flash-through-white`(白フラッシュでクロスする切替シェーダー)、`npx hyperframes add beat-accent`(拍に合わせた単発のフラッシュ+スケールパルス)。
- **音との合わせ方**: ピーク頭にシャッター音/爆発音、直後に高音の耳鳴り(sine 4〜8kHz)を0.5秒かけて減衰させ、無音気味に落とすと痛みが出る。
- **難易度/適性**: ★(最も簡単で効果が高い)。
- **AI動画生成プロンプト**: `Blinding light flash over [Subject], bulb or explosion or memory sting, the frame going to white then returning, not a persistent source-linked flare.`

### ライトリーク / Light Leak  (`effects/light-leak`)
- **一言**: レンズを通らない光がフィルムやセンサーに直接入り、画面の縁からオレンジや赤の霧として画像を侵す。
- **物語での役割**: カメラ本体が壊れている・時間が傷んでいるという、アナログの記憶や事故の質感を与える。写っているランプとは無関係の「画面の外からの傷」。
- **使う/使わない**: 記憶・事故・手持ちフィルム感のカットに、縁から入れて短く切替の句読点にする。クリーンなデジタル室内に常時かける「懐かしい調子」としては使わない(安易な懐古になる)。
- **よくある失敗**: 画面中央・写っている太陽の位置にゴールドの靄を置いてリークと呼ぶ(それはフレア)。電球に赤い輪が付く(ハレーション)。
- **似た技法との違い**: レンズフレアはガラスを通って光源をゴースト化する。リークはガラスを迂回して縁から入る。フィルムグレインは質感で、霧ではない。
- **HyperFramesでの作り方**: 縁起点の暖色グラデーションを2〜3層(例: 左端中心の `radial-gradient(ellipse at 0% 40%, #ff5a1f 0%, #ffb347 30%, transparent 70%)` と、上端からの赤の細い帯)。`mix-blend-mode: screen`(強い白飛びなら `plus-lighter`)で重ね、位置を 5〜15% ずつゆっくり漂わせ(t の関数、sin合成)、opacity は 0→0.8→0.2 を1〜1.5秒の山形(power2.inOut)にして**有限時間で終わらせる**。画面内の光源には反応させない。既製: `npx hyperframes add organic-light-leak-overlay`(記憶ビート・動機付きの切替向けのCSS重ね)、`npx hyperframes add light-leak`(光漏れを乗せたシェーダー遷移)。粒状感は `npx hyperframes add grain-overlay` を弱く足すとフィルムらしくなる。
- **音との合わせ方**: フィルムが引っかかるようなノイズ/低いフリッカーを山に合わせる。
- **難易度/適性**: ★(既製部品で足りる)。
- **AI動画生成プロンプト**: `Analog light leak washing [Subject], orange or red fog eating the frame edge, unfiltered light on the emulsion, not a source-linked lens flare.`

### マスキング / Masking  (`effects/masking`)
- **一言**: 双眼鏡・鍵穴・図形窓のような硬い輪郭で画面を切り、「見ること」自体を形として見せる。
- **物語での役割**: 観客に登場人物と同じ見方を強いる。のぞき・監視・覗き見の視点が、暗い周囲と穴の中の写真として伝わる。
- **使う/使わない**: のぞき見・双眼鏡・鍵穴越しのビートに、シーン丸ごと維持して使う。単なるトリミングや、見ること自体が主題でない場面の飾りには使わない。
- **よくある失敗**: 周囲が柔らかく暗いだけのビネットで済ませる。穴の形に合わせて構図を作らず、被写体が欠ける。
- **似た技法との違い**: フレームインフレームは現場にある窓・扉を使う。アイリスは円が開閉する遷移。マスキングは形が「見る行為」で、持続して居座れる。アスペクト比切替は容器自体が変わる。
- **HyperFramesでの作り方**: SVG `<mask>`(黒背景に白の図形)を映像/シーン層に適用するか、前面に黒の穴あきオーバーレイを置く。双眼鏡: 半径 画面高の38%の円2つを中心間隔 画面幅の約22%で並べ、境界は羽根無し(1px程度のぼかし)。鍵穴は円+台形のpath。穴の中の絵は scale 1.1〜1.2 とゆっくりしたドリフト(±1.5%)で「手で構えている」感じに。ターゲットを追う動きは穴の中の絵だけ動かし、穴は固定。開閉の入場は `npx hyperframes add iris-reveal`(円 clip-path が開く)や `sdf-iris`。羽根付きスポットライト(`yt-feather-highlight`)は羽根が柔らかいのでマスキングには向かない。
- **音との合わせ方**: 呼吸音・衣擦れ・ピント環の機械音をやや前に出すと、のぞいている主観が強まる。
- **難易度/適性**: ★(SVG maskだけ)。
- **AI動画生成プロンプト**: `Masked frame around [Subject], a hard shape cutting the picture, binoculars or keyhole, photographed interior, opaque surround, composed for the hole.`

### モーフ(編集としての変形) / Morph  (`effects/match-morph`)
- **一言**: 対応する形や顔の頂点を補間して、ある像を別の像へ連続的に「なる」ように変える。不透明度のクロスフェードではない。
- **物語での役割**: 同一性が数秒だけ不安定になり、新しい形が固まる。変身・仮面と顔・人から人への移行を、観客に「見せる」ことで成立させる。
- **使う/使わない**: 顔が別の顔へ約6秒かけて移る、液体金属が人になる、など変化そのものが主役の1回。2つの全身像をクロスフェードして「モーフ」と称するのは使わない。
- **よくある失敗**: 結局2枚のゴーストが残るだけ(ディゾルブ)。対応点が無く、中間状態が設計されていない。
- **似た技法との違い**: ディゾルブは不透明度で交替し形の対応が不要。ダブルエクスポージャーは両方を保持する。マッチカットは形の類似で切り、補間しない。
- **HyperFramesでの作り方**: 方式は「形の補間」と「画像のワープ」の2系統。①SVGパス/ベクターなら、2つのpathを同じ点数N=128〜256に再サンプリングして点ごとに lerp(`onUpdate`で `d` を再計算。1本のpausedタイムライン、power2.inOut、2〜6秒)。点の対応(目↔目、輪郭↔輪郭)を先に揃える。②写真はWebGLメッシュワープ: 8×8の制御格子にランドマーク差分をかけ、A を +t、B を −(1−t) だけ動かし、色は smoothstep(0.3,0.7,t) で混ぜる。部位ごとに t をずらす(目→鼻→輪郭)と「中間が設計された」見え方になる。③アイコン/UIなら既製 `npx hyperframes add icon-morph-beat`、`morph-swap`、文字なら `morph-text`(SVG閾値のゲル状)。ランドマークは事前に座標JSONへ焼き、実行時に検出しない。`cross-warp-morph` はノイズ駆動のシェーダー遷移で、顔の対応点は持たない。
- **音との合わせ方**: 滑らかなグリッサンドや、液体的なうねりの低音で連続性を支える。
- **難易度/適性**: ★★〜★★★(写真の顔は難しい。ベクター/UI/文字なら★★)。
- **AI動画生成プロンプト**: `[Subject] morphs into [another form or face] over 6 seconds, continuous transformation with features traveling, not a dissolve, not a cut.`

### ミックストメディア / Mixed Media  (`effects/mixed-media`)
- **一言**: 実写、イラスト、文字、ストック素材など撮り方の違う素材を、1つの平面で衝突させる。
- **物語での役割**: ニュース・記憶・身体が1つの媒体に収まらないことを、継ぎ目を見せたまま伝える。滑らかな合成では嘘になるときの選択。
- **使う/使わない**: 報道・資料・手書きが混在する物語の1ビートに。写真的統一感がほしい場面にステッカーのように貼らない。
- **よくある失敗**: 単一のグレード・粒状感のまま文字を載せるだけで終わる(質感が1種類)。同じ写真を細切れにしただけのコラージュ。
- **似た技法との違い**: コラージュは静止画を積む。ミックストメディアは撮り方の違うメディアの衝突。タイポグラフィは文字が主役。
- **HyperFramesでの作り方**: 層ごとに「別の素材らしさ」を割り当てる。①実写/写真層: `grayscale(.3) contrast(1.2)`+細かい粒。②イラスト層: SVG線画+`feTurbulence`(baseFrequency 0.02、seedを8fpsで切替)+`feDisplacementMap`(scale 3〜5)の「線の揺れ」。③ストック層: ハーフトーンやドット化(`npx hyperframes add halftone-field` が参考)で別の質感に。④文字層: タイプ/手書き。層の縁は clip-path の不規則polygon(seed付きPRNG)で破り、各層のコマ送りを別にする(写真は30fps、イラストは8〜12fps)。中心の被写体は1つ決めて読めるようにする。紙・テープ・フラッシュ装飾の既製: `npx hyperframes add freeze-frame-dressing`。
- **音との合わせ方**: 素材ごとに別の音(タイプ音・紙擦れ・放送ノイズ)を鳴らして衝突を聞かせる。
- **難易度/適性**: ★★(設計と素材集めが肝)。
- **AI動画生成プロンプト**: `Mixed media around [Subject], live action, type, illustration and stock colliding in one plane, visible edges, no single seamless grade.`

### モーフィング(幾何学的変形) / Morphing  (`effects/morphing`)
- **一言**: ランドマークの対応づけによる幾何補間で、ある形・顔を別の形へ連続変形させる。フェードではない。
- **物語での役割**: 変化を「目の位置は保ったまま輪郭が動く」対応関係として見せ、アイデンティティの移行を観察させる。
- **使う/使わない**: 数秒の連続した視界で一方が他方になる場面に。共通のランドマークが無い無関係な2ショットのつなぎとしては使わない。
- **よくある失敗**: 不透明度だけが変わる(ディゾルブ)。中間点の設計が無く顔が溶ける。背景まで一緒に引きずられる。
- **似た技法との違い**: 「モーフ(編集)」はワープを2ショットの接合に使う。こちらは幾何補間そのもの。トランスフォーメーションは世界や状態の入れ替えを含む。
- **HyperFramesでの作り方**: canvas 2D の三角形メッシュワープが現実的。①2枚の画像に同じ数・順番のランドマーク(目・眉・鼻・口・顎・輪郭で約20点+画面の周囲に固定の8点)を事前JSON化。②Delaunay分割した三角形を、各三角形について A→中間形、B→中間形のアフィン変換で `ctx.setTransform` し、clip→drawImage。③中間形 = lerp(PA, PB, t)、色 = A の warped を (1−s)、B の warped を s で重ね、s = smoothstep(0.3,0.7,t)。t は proxy tween の onUpdate から取る純関数で、毎フレーム全描画。④背景は周囲固定点で動かさず、前景を別層に切り離すと部屋が引きずられない。⑤部位ごとに t をずらす(目0→0.6、口0.2→0.8、輪郭0.3→1)。GPUが使えるなら同じ数式をWebGLで。ベクターなら Morph の項のpath補間が楽。
- **音との合わせ方**: 声や楽器の連続的なピッチ変化(グライド)を重ねる。
- **難易度/適性**: ★★★(ランドマーク作成が必要)。実写の顔写真のワープは不向き寄り。代替は2つのベクター顔/シルエットのpath補間。
- **AI動画生成プロンプト**: `Morph of [Subject] into another state, continuous transformation with eyes aligned, identity as a dissolve you can watch, no cross-dissolve of unmatched poses.`

### ナイトビジョン / Night Vision  (`effects/night-vision`)
- **一言**: 微光増幅装置の見え方、つまり緑の蛍光体色・粗い粒子・光源のブルーム・ゴーグルの枠として暗闇を映す。
- **物語での役割**: 追う側/隠れる側の視点。世界が筒になり、解像度の悪さと粒子が「装置越しに見ている」緊張を作る。
- **使う/使わない**: 襲撃・found footage・ゴーグルを着けた地下室など、**装置の主観**として使う。月夜の屋外や、熱を見るサーマルの場面、ただ緑に染めた夜景には使わない。
- **よくある失敗**: 通常のコントラストのまま色相だけ緑にする(単なる緑グレード)。粒子・ブルーム・枠が無い。
- **似た技法との違い**: サーマルは放射された熱をカラーパレットにする。赤外線写真は反射率を撮る。ナイトビジョンは増幅された光で、粒子とブルームが特徴。
- **HyperFramesでの作り方**: 土台の映像(暗い場面でも可)に SVG フィルタを当てる。①輝度→緑: `feColorMatrix type="matrix"` values `0.045 0.09 0.017 0 0  0.3 0.59 0.11 0 0  0.06 0.118 0.022 0 0`(輝度をGに集め、R/Bを弱く)。前段で `contrast(1.6) brightness(1.3)` で白飛び気味に。②ゲインノイズ: canvasに毎フレーム seed=フレーム番号 の mulberry32 でノイズを描き(半解像度を `image-rendering: pixelated` で拡大)、`mix-blend-mode: overlay`、opacity 0.35〜0.5。数フレームに1度の明るい点滅(scintillation)を少量。③ブルーム: 複製を `blur(6px) brightness(1.8)` で `screen`。④枠: 双眼鏡の2円マスク(Masking参照)や `radial-gradient` の周辺減光、細い走査線、微小な水平ジッタ(±1〜2px、seed付き)。⑤IR照射のホットスポット: 画面中央をやや明るく。ffmpeg後処理なら `-vf "format=gray,format=rgb24,colorchannelmixer=rr=0.15:gg=1:bb=0.2,eq=contrast=1.6:brightness=0.08,noise=alls=35:allf=t,vignette"`。既製のナイトビジョン部品は無い。
- **音との合わせ方**: 呼吸、装置の高い電子音(約8kHz)、近距離音を強調。
- **難易度/適性**: ★★(フィルタ重ねで再現可)。
- **AI動画生成プロンプト**: `Night-vision green phosphor of [Subject], grainy image intensification, blooming lamps, goggle or sight framing, surveillance or military eye, not a thermal palette.`

### オブジェクトポータル / Object Portal  (`effects/object-portal`)
- **一言**: バッグ・画面・扉など「そこに通じるはずのない小道具」が、別の空間への入口になる。小道具自体がカットになる。
- **物語での役割**: 観客が既に信じている物体を通して、場所を一気に飛ばす。ファイルキャビネットがトンネルに、鏡が廊下に、スマホが人を飲み込む。
- **使う/使わない**: 人が小道具に入って部屋に収まらない場所へ着く1ビートに。ただの扉の周りを光らせるだけ、壁をカメラが突き抜けるだけの場面(それはパススルー)には使わない。
- **よくある失敗**: 厚みの無い光る枠で済ませる。周囲の部屋まで一緒に溶ける。縁の奥行き(視差)が無い。
- **似た技法との違い**: パススルーは建築をカメラが貫く。プロジェクションは面に絵を載せる。ポータルは物体の開口部が別空間へ通じる。
- **HyperFramesでの作り方**: 3層構成。①手前の部屋層(この世界)。②ポータル開口: 小道具の縁(厚みのあるリム。SVGで内側に inner-shadow、外側に接地影)。③開口の内側に clip-path(ellipse/roundedrect)をかけた**遠い空間**の層。カメラ(またはリム)が動くと、内側の絵は逆向きに視差移動(リム移動量の0.3〜0.5倍)させて穴の奥行きを出す。通過は2コピー方式: 人物の「外にいる部分」は開口外のclip、「入った部分」は開口内のclipで別描画し、リムをまたいで切り分ける。最後は開口中心を原点に全体を scale 1→6〜10(power3.in、1.0〜1.5秒)で押し込み、遠い空間に差し替える。既製: `npx hyperframes add vfx-portal`(html-in-canvas+WebGLのポータル、内容は追加後に確認)、`npx hyperframes add wireframe-portal-title`(ワイヤーフレームのポータルから文字が出る)。
- **音との合わせ方**: 吸い込みの低周波スウィープ、通過で空間の残響を切り替える。
- **難易度/適性**: ★★(2コピーの切り分けが肝)。
- **AI動画生成プロンプト**: `Object portal through [Subject], a prop opening onto another space, a bag, a screen or a doorway that should not lead there, surrounding room stays in this world.`

### パーティクル / Particles  (`effects/particles`)
- **一言**: 塵・火花・花粉・灰などの数えられる粒子で空気を満たし、光を受けて一粒ずつ輝かせる。
- **物語での役割**: 光の筋を「数えられる空気」にし、静けさ・神聖さ・戦いの後・小麦粉の舞う台所などの質感を作る。
- **使う/使わない**: 逆光の室内や納屋、爆発の余韻など、粒が主題の場面に。空気は見えないはずの場面や、粒子が被写体を覆い隠すほど多い場面には使わない。
- **よくある失敗**: 画面全体の霧/ミストの重ね(粒が無い)。逆光が無く粒に光が乗らない。粒の種類が不明。
- **似た技法との違い**: ダストモートは光の筋の中の塵に限定。ボリュメトリックライトは光の筋そのもの。パーティクルは散乱体を物として数える。
- **HyperFramesでの作り方**: canvas 2D で、粒ごとの初期値(位置・速度・半径1〜4px・位相)を mulberry32(seed) で1度だけ生成し、位置は t の閉形式で求める(`x = x0 + vx·t + A·sin(ωt+φ)`、周回は剰余)。毎フレーム全消去・全再描画、`globalCompositeOperation='lighter'`。**光の筋マスク**(`clip-path: polygon`の斜めの帯やradial-gradient)の内側でだけ明るく(α=筋内で0.8、外で0.1)、きらめきは `0.5+0.5·sin(t·f+φ)`。奥の粒は大きく `blur(2px)`、手前は小さく鋭く。数は100〜300粒。塵: ゆっくり下降+横ゆらぎ、火花: 上昇+橙→赤+寿命でフェード。既製: `npx hyperframes add confetti`(重力つきの決定的な粒子)、`particle-image-reveal`(粒が収束して画像が現れる)、`particle-text-dissolve`(文字↔粒子雲)、`caption-particle-burst`(キーワードで粒子バースト)。
- **音との合わせ方**: 粒が弾けるなら高域の小さなパチパチ、静かな粒には音を足さず無音で見せる。
- **難易度/適性**: ★(canvasで容易)。
- **AI動画生成プロンプト**: `Particles around [Subject], dust, sparks or pollen, backlit so each speck catches light, discrete countable bits, no fog wash.`

### フォトグラメトリ調 / Photogrammetry  (`effects/photogrammetry`)
- **一言**: 多数の写真から3Dを再構成した「スキャンされた現実」の見た目。引き伸ばされたテクスチャ・欠け・継ぎ目が証拠になる。
- **物語での役割**: 実在の場所を、探索できるモデルとして見せる。測量・記録・少し仮想的な感触。物理シミュレーションの証明にはならない。
- **使う/使わない**: 実在の場所をモデルとして周回・点検するカットに。手作りのミニチュア感を出したいとき、科学的レンダーをスキャンと偽るときには使わない。
- **よくある失敗**: 絵本のようなジオラマ調、または継ぎ目の無いクリーンなゲームレンダー。
- **似た技法との違い**: ジオラマは模型の照明。フォトグラメトリは写真テクスチャとスキャン誤差。ビデオゲームは作られた資産。
- **HyperFramesでの作り方**: Three.js で「2.5Dスキャン」を作る。①細分化した平面(256×256分割)に写真をテクスチャとして貼り、深度マップ(事前に作った白黒画像)で頂点を押し出す。②カメラは小さな弧(±12〜20°、power2.inOut、4〜6秒)を回り込む。急な深度差の面は、斜めから見るとテクスチャが縦に引き伸ばされる(これが「それっぽさ」)。③穴: 深度勾配が大きい箇所は fragment で `discard` して欠けを出す。④光は写真由来のまま(ライティング無し)か、弱い CG キーを重ねる。⑤ワイヤーフレーム/ポイントクラウド表示をオーバーレイすると「再構成中」の演出になる。毎フレーム t でカメラ位置を決定的に更新。深度マップが必要で、実景のスキャンそのものは作れない。
- **音との合わせ方**: 機械的なスキャン音(細かなクリック、走査音)を軽く。
- **難易度/適性**: ★★★。実写スキャンの再現は不向き。代替: 深度マップ付きの2.5D視差(上記)や、ワイヤーフレーム+点群の演出。
- **AI動画生成プロンプト**: `Photogrammetry look of [Subject], scanned space, slightly wrong mesh, stretched photo texture, a hole or seam, orbiting inspection camera, not a toy diorama.`

### プロジェクション(映像の投影) / Projections  (`effects/projection-mapping`)
- **一言**: 映像を面に投影し、それを撮影する。フロント/リアプロジェクション、建築へのマッピングなど、セット自体がスクリーンになる。
- **物語での役割**: 巨大な背景と生身の前景を同じ画面に収める、または建物が顔や模様をまとう。「メディアが空間になる」。
- **使う/使わない**: 前景の俳優と背景プレートの視点が共通する、固定ワイドの合成や、建物へのマッピングに。ゴーストのように透過した顔を部屋に重ねる用途(それはダブルエクスポージャー)には使わない。
- **よくある失敗**: 面に乗らず浮いた透明のオーバーレイ。消失点の不一致。背景だけが視差で滑る。
- **似た技法との違い**: ダブルエクスポージャーは投影無しで2つの記録を重ねる。プラクティカルライティングは照明であって画像ではない。
- **HyperFramesでの作り方**: 「面に載せる」を3D空間として作る。①CSS 3D: 親に `perspective: 1200px; transform-style: preserve-3d`、壁面を `translateZ`+`rotateY` で配置し、投影画像を同じ面の子にして面と同じ変換を受ける(`matrix3d` で四隅合わせも可)。壁の質感(凹凸・目地)は `mix-blend-mode: multiply` の画像で重ね、投影層は `screen`/`overlay`、opacity 0.7〜0.9。②視点共有: カメラ(親)を動かすと投影も一緒に追従する=視差が壁面と整合する。③前景への色かぶり: 投影の平均色の弱いグラデを前景に `overlay` 4〜8%で当てて「光が当たっている」ことにする。④リアプロ(車窓): 窓のclip-path内でプレートを一定速度で流し、前景だけに微小なカメラシェイク(`camera-shake`)。モニター風の質感は `npx hyperframes add yt-screen-warp`(スキャンライン・ビネット・3D反り)。
- **音との合わせ方**: プロジェクターの低いモーター音や映写機のノイズを環境音に。
- **難易度/適性**: ★★(CSS 3Dの面合わせ)。実写の前景を同一光学で撮る合成は不向き。代替: 前景を手前の層、背景を面に貼った層として3D構成する。
- **AI動画生成プロンプト**: `Projected imagery crawling over [Subject] and architecture, a plate on a screen or faces on walls, foreground lit to match the projection, in-camera process, not a double-exposure ghost.`

### ラックフォーカス / Rack Focus  (`effects/rack-focus`)
- **一言**: 構図を変えず、ピントの合う面を近い被写体から遠い被写体へ(またはその逆に)連続の1ショット内で移す。
- **物語での役割**: カットせずに「誰がこのショットの主役か」を受け渡す。手がかりから顔へ、追う側から追われる側へ。ゆっくり=文、素早い=ジャブ。
- **使う/使わない**: 机の鍵から、戸口の人物へ約2秒で視線を送る場面に。両方がシャープであるべき場面(ディープフォーカス)や、カメラが物理的に動くべき場面には使わない。
- **よくある失敗**: ピントが動かず絵がディゾルブする。ズームで代用する。被写体が別物に化ける。
- **似た技法との違い**: シャローフォーカスは静止した薄い面。ラックはその面が動く。スプリットディオプターは2距離を同時にシャープに保つ。
- **HyperFramesでの作り方**: 奥行き別に最低2層(近景・遠景)を用意し、焦点距離 f を proxy tween で動かす(`{f: near→far}`、power2.inOut、1.5〜2.5秒。素早い「スナップ」は0.3秒 power4.out)。各層のぼかし半径を onUpdate で `blur_px = K·|d − f| / d`(K=12〜20程度、dは層の距離)に設定。ぼかしは焦点が離れるほど大きく、合った層は0px。ピント移動中に、前景を約1〜2%だけ拡縮(レンズブリージング)させると実写らしい。ハイライトはぼけると円盤(ボケ)になるので、輝点だけ別canvasで半径 blur_px の円として描く。既製: `npx hyperframes add rack-focus`(WebGLで本物の絞り形ボケ。画角の隅は猫目になる。近景・遠景の2深度を変数で指定、夜景付き)、`npx hyperframes add focus-rack`(2枚のカードで同期ぼかし・暗転・スケール・視差)。
- **音との合わせ方**: ピントが遠景へ移る瞬間に音の焦点(近景の音→遠景のセリフ)も移すと一体感が出る。
- **難易度/適性**: ★★(既製部品あり、層分けの設計が要る)。
- **AI動画生成プロンプト**: `Focus racks from [foreground element] onto [Subject] over about two seconds, shallow depth of field, locked camera, no zoom.`

### アスペクト比切替 / Ratio Switch  (`effects/ratio-switch`)
- **一言**: 画面の枠そのもの(アスペクト比)が広がったり閉じたりして、物語の位相が変わったことを示す。画像は引き伸ばさず、見えていなかった部分を現す/切り詰める。
- **物語での役割**: 枠が登場人物になる。時代・自由・拘束を「映画の端」として体感させる。例: グランド・ブダペスト・ホテル(2014)。
- **使う/使わない**: 登場人物が世界を押し開く場面、時代が変わる場面に1〜2回。ズームアウトの言い換えとしては使わない(枠が変わらずショットサイズだけ変わる)。
- **よくある失敗**: 画像を引き伸ばして人が太る。マットを動かさずレンズだけが寄る。
- **似た技法との違い**: マスキングは安定した容器の中に図形の穴を開ける。アスペクト比切替は容器自体が変わる。
- **HyperFramesでの作り方**: 最も簡単な部類。最大の比率(例 2.39:1 を作画できるワイド)で1920×1080の絵を用意し、ステージの `clip-path: inset()` か左右/上下の黒帯divで見える範囲を切る。4:3(中央1440×1080)→ワイドは、左右の帯の幅を 240px→0 に power3.inOut で0.8〜1.2秒。2.39:1に閉じるなら上下の帯を 0→約138pxへ。**中身は scale せず、被写体の幾何を保つ**(引き伸ばし禁止)。両方の比率で被写体が欠けない安全領域を中央に構成し、広がった領域には新しい情報(周囲の景色)を描いておく。カメラが固定でも、枠の動きがイベントになる。
- **音との合わせ方**: 枠が開く瞬間に音場も広げる(モノ→ステレオ、残響を増やす)と物語の位相が変わる。
- **難易度/適性**: ★(clip-pathの帯だけ)。
- **AI動画生成プロンプト**: `Aspect-ratio switch on [Subject], the frame itself widening from 4:3 to 2.39:1, a visible crop or reveal of extra picture, image not stretched.`

### スケールシフト / Scale Shift  (`effects/scale-shift`)
- **一言**: 同じ部屋の中で人の大きさが急に巨大/極小になる光学的イベント。家具・影・接地を新しい比率に合わせる。
- **物語での役割**: 相対的な大きさが物語になる。台所のテーブルが風景になり、手が建物になる(不思議の国のアリス的物理)。なお同名が『ダンケルク』のような時間軸の不均等を指すこともあるが別物。
- **使う/使わない**: 身体と部屋の大きさの関係が事件になる1カットに。単なるクローズアップや、時間軸の編集には使わない。
- **よくある失敗**: 顔が大きいだけで部屋が普通のまま(ただのアップ)。影や接地が新しい大きさに合わない。
- **似た技法との違い**: フォースドパースペクティブは2つの実寸を1つの焦点面で同じ大きさに見せる。スケールシフトはその関係自体の変化。マグニフィケーションは極端な接写で全身が縮むわけではない。
- **HyperFramesでの作り方**: 実写には不向きで、ベクター/CSS 3Dの構成で作る。部屋(床・壁・家具)を1層、人物を別層にし、**人物だけ**を足元原点(`transform-origin: 50% 100%`)で scale 1→0.08(または1→6)、power3.inOut、1.2〜2秒。接地影も同じ比率で拡縮し、巨大化では影を大きく・薄く、極小では小さく濃く。家具との接触(椅子に座るなど)は、縮小後の位置を足元座標から再計算して置く。部屋の遠近(消失点・床のタイル)は固定。カメラが追うなら、頭の位置に合わせて部屋を逆パンする。人物の見た目が拡縮で崩れないよう、ベクターで描く。
- **音との合わせ方**: 縮小で声のピッチを上げ、巨大化では下げて残響を足す。
- **難易度/適性**: ★★(ベクター代替)。実写・AI人物の等身変更は不向き。
- **AI動画生成プロンプト**: `Scale shift of [Subject], the body suddenly giant or tiny against the same room, matching shadows and contact, not a mere close-up.`

### セルフィーツイン / Selfie Twin  (`effects/selfie-twin`)
- **一言**: スマホを持った腕の長さの広角で、同じ顔が2つ写る。自分自身とポーズを取る二重像。
- **物語での役割**: アイデンティティのギャグ、自分の像から逃げられない人物、社会的な分身。コンパクトカメラの歪みが「撮った」感を作る。
- **使う/使わない**: 同一人物が二人でスマホ撮影風に収まるジョークに。部屋の広い2ショットや、1人がレンズを見るだけの場面には使わない。
- **よくある失敗**: 似た別人を並べる。望遠で撮ったようなスマホらしくない画角。
- **似た技法との違い**: デュプリケーションは劇的カバレッジでの分身。セルフィーツインはスマホ腕の文法。第四の壁破りは1人がレンズを見る。
- **HyperFramesでの作り方**: 実在の顔写真や生成顔の「同一人物2人」はコードでは不向き。代替は、ベクターのキャラクターを1つ描き、2体に複製して撮影UIの中に収める。①キャラは同じSVG `<use>` を2回(片方を scale 1.08 で少し手前、`rotate(±4deg)`で傾ける)。②広角歪み: `feDisplacementMap`(放射状グラデの変位マップ、scale 20〜30)か、WebGLで `uv' = c + (uv−c)(1 + 0.15·r²)` の樽型歪み。③スマホUI: シャッターリング、ピンチ枠、フラッシュの白(Light Flashの手順)、画面の端に親指。④光源は1つ(画面側からの白いキー)で、2体とも同じ向きの影。
- **音との合わせ方**: カウントダウン音とシャッター音(「カシャ」)で撮影の瞬間を区切る。
- **難易度/適性**: ★★(ベクター代替)。実写・AIの同一人物生成は不向き。
- **AI動画生成プロンプト**: `Selfie twin of [Subject], the same person twice in a phone-arm wide frame, compact-camera distortion, identity as a double take, not two lookalike actors.`

### シャドウボックス / Shadow Box  (`effects/shadow-box`)
- **一言**: 切り絵の黒いシルエットを奥行きに積み重ね、硬い逆光の前で見せる、闇のジオラマ。
- **物語での役割**: 騎手・木・宮殿が別々の面に並ぶ「紙の演劇」。顔の質感ではなく形と層で語る寓話的な画。
- **使う/使わない**: 夜の紙芝居のような1ビートに。顔に肌と目の光が必要な場面や、実景で単独の人物が逆光に立つだけの場面には使わない。
- **よくある失敗**: 面が1枚しかない(ただのシルエット)。肌の質感や塗られた顔が入り、模型になる。
- **似た技法との違い**: シルエットは1人の逆光。ジオラマは作り込まれた小世界。シャドウボックスは複数の黒い層。
- **HyperFramesでの作り方**: CSS 3Dで6〜10枚の層を作る。親に `perspective: 1200px`、各層を `translateZ(−100〜−1400px)`、背景に強い逆光グラデーション(暖色の radial-gradient)。各層は SVG の黒いシルエット。**奥ほど少し明るく**(層の色 = 黒と逆光色を奥行き0〜40%で混ぜる)すると空気遠近が出る。層の間に半透明の霧グラデ(opacity 0.1〜0.2)。カメラの忍び寄りは、親を `translateX ±40px`(または rotateY ±3°)で6〜10秒ゆっくり動かし、層ごとの視差を自動で得る。縁に `feTurbulence`+`feDisplacementMap`(scale 2)で紙の切り口の揺れ。顔には塗りを入れない。既製の骨格: `npx hyperframes add camera-rig-depth-stack`(奥行き・視差・ピント移動のカメラリグ)。
- **音との合わせ方**: 乾いた紙/木の音、薄い管弦、演劇の幕の音など、舞台的な音色にする。
- **難易度/適性**: ★★(層の設計次第)。
- **AI動画生成プロンプト**: `Shadow-box of [Subject], layered cut-out silhouettes on several planes, hard backlight, no fill on figures, depth as stacked paper, diorama of darkness.`

### シャローフォーカス / Shallow Focus  (`effects/shallow-focus`)
- **一言**: 狭い被写界深度で一面だけを鮮明にし、前景・背景を光学的に落とす。絞り・焦点距離・距離の組み合わせで決まる。
- **物語での役割**: 光学的な孤立。世界は存在するが、レンズが報告を拒否している。排除によって生まれる親密さ。
- **使う/使わない**: 切符売りの手前の目だけが鮮明で、駅の人混みが読めない形になる、のような「他は招かない」場面に。奥の人物の反応が読めないといけないブロッキングには使わない。
- **よくある失敗**: 髪が切り抜き風で背景が円盤(ボケ)の無い単なるぼかし(写真ではない)。両耳とも同じくらいシャープ。
- **似た技法との違い**: ボケはぼやけ方の見た目、シャローフォーカスは薄い面の存在。ラックフォーカスはその面が動く。
- **HyperFramesでの作り方**: 被写体層を鮮明(0px)、背景層を奥行きに応じてぼかす(`filter: blur(8〜24px)`、距離が遠いほど大きく)。**層ごとに分離して**ぼかす(髪の縁を切り抜きではなく、被写体層の縁を自然に残す)。ボケの円盤は、背景の輝点を canvas に半径10〜40px・淡いリング付きの円で描き、`screen` で重ねる(縁がやや明るい円)。焦点面を目の位置に決め、顔が動くなら blur の基準面を追従させる。画面端の猫目ボケやスワールが要るなら `npx hyperframes add rack-focus`(WebGL・多角形の絞りボケ)を静止状態で使う。実写に後処理で作るなら、マットがあれば ffmpeg で `boxblur`+`maskedmerge`(被写体マスクで鮮明部を残す)。
- **音との合わせ方**: 背景の環境音を下げ、被写体の近い声・息を前に出す。
- **難易度/適性**: ★(ベクター/層構成なら容易。実写のマット作りは別手間)。
- **AI動画生成プロンプト**: `Very shallow focus on [Subject], T1.4, near eye sharp, background dissolved into optical discs, intimacy by exclusion, not a cutout mask.`
