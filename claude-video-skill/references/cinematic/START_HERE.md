# 映像技法リファレンス START HERE

424技法(出典: melies.co/cinematic-techniques を要約・再構成)を、**コードで映像を作る人向け**に「物語での役割 / 使う・使わない / 失敗 / HyperFramesでの作り方(数値付き)」へ翻訳したもの。
場面を設計する時に引く辞書。全部を読む必要はない。**場面カード(`../shot-spec-template.md`)を書く → 必要な技法だけ引く**。

> **出典と権利**: 技法の解説は melies.co/cinematic-techniques の内容を日本語で要約・再構成し、HyperFramesでの実装レシピ(数値・数式・部品名)は本スキル独自に追加したもの。各エントリ末尾の「AI動画生成プロンプト」は、出典サイトの雛形を短くした英語の一行(AI動画生成ツールに貼る用途の参考)。出典サイトの全文の転載ではないので、詳しい解説・映画の具体例・動画サンプルは出典ページを参照。

## 1. 引き方(3ステップ)
1. **場面の役割**(観客に何を起こすか)を1文で決める → 下の「§3 目的 → 技法」で第一候補を拾う。
2. 技法の本文を探す: `INDEX.md`(全技法の表。ファイル名・一言・難易度)か、`grep -n '`camera-movement/dolly-zoom`' references/cinematic/*.md`。
3. その**エントリだけ**を読み、場面カードに「技法名・数値・つなぎ」を書き写す。担当(サブエージェント)には**エントリの該当節を読むよう指示**する(丸投げで「かっこよく」と言わない)。

ファイル: `camera-movement-1.md` / `camera-movement-2.md`(カメラの動き)・`framing-angles.md`(ショットサイズとアングル)・`composition.md`(構図)・`lighting.md`(光)・`color-atmosphere.md`(色と大気)・`lenses-time.md`(レンズと時間)・`editing.md`(編集と遷移)・`effects-1.md` / `effects-2.md`(光学効果)・`genre-viral.md`(ジャンル/流行のルック)。各ファイルの冒頭に**そのグループの選び方ガイドと共通の実装方式**がある(先に読むと各エントリの数値の前提が分かる)。

## 2. 映画の文法 10の原則(各カテゴリの核心)
1. **動きは、最後のコマが最初のコマに無かった事実を見せる時だけ**。新しい場所・力関係・画面外にあったもの。何も増えないなら動かさない(静止が正解のことも多い)。
2. **ショットサイズは「文」**。サイズを変えるのは、新しいサイズが前のコマに無かった事実を見せる時だけ。同じサイズが続くとスライドショーになる。
3. **アングルは地位を決める**(誰も話す前に)。切り返しは相手の体に合わせた高さで。
4. **光は影の決定**。光源(窓・ランプ・太陽)→キー側→硬さ→色の順に決める。目は最も明るい読めるものへ行く。
5. **構図は視線の通り道**。誰が空間を所有し、何が遮られ、縁はきれいか汚れているかを図で言う。
6. **色は時間・場所・光源の約束**。色の変化は「出来事」で、ずるずる流さない。5秒前がタングステンなのに急にティール&オレンジにしない。
7. **レンズは「立ち位置」が本体**。圧縮感・遠近の誇張は焦点距離でなく距離で決まる。焦点距離を感情として書かない。
8. **時間は素材**。ランプやフリーズは当てる拍を決める。時間が意味を変えないなら通常速度のまま。
9. **つなぎは両側を書く**。出ていく絵と入ってくる絵。何も共通しなければマッチではなくただの2ショット。
10. **効果は物理的な原因を書く**(ガラス・ピント・二重露光)。「フィルターを重ねる」ではない。ジャンルルックは光・配色・レンズ・動線の総体で、ジャンル名は最後に付ける。

## 4. 必修30技法(これだけ覚えれば場面は組める)
- **カメラ**: ドリーイン / プッシュイン / パン / ウィップパン / クラッシュズーム / クレーンアップ / ドリーズーム / 固定カメラ / 360度オービット
- **サイズ・アングル**: クローズアップ / ミディアム / ロング(エスタブリッシング) / ローアングル / ハイアングル / ダッチアングル
- **構図**: 三分割 / 中央フレーミング・シンメトリー / ネガティブスペース / レイヤード・デプス(多層の奥行)
- **光・色**: キーライト+フィル / ローキー・ハイキー / リムライト・バックライト / シルエット / ゴールデンアワー / ティール&オレンジ・スプリットトーン
- **時間・編集**: スローモーション / スピードランプ・フリーズ / スマッシュカット / マッチカット / ディゾルブ・フェード / モンタージュ・クイックカット
- **効果**: ビネット / フィルムグレイン / ボケ・ラックフォーカス / ライトリーク / 色収差
- 本質は「**多層の奥行(視差)**」「**光源の統一**」「**拍に乗せた編集**」の3つ。

## 5. 似たカットを避ける: 隣接場面の差分チェック
前の場面と次の場面で、次の5軸のうち**少なくとも3つ**を変える(同じが続くと「使い回し」に見える)。
| 軸 | 例 |
|---|---|
| ショットサイズ | ロング → クローズアップ |
| カメラの動き | 固定 → ドリー → 手持ち |
| 光の方向・硬さ | 逆光の硬い光 → 窓光の柔らかい光 |
| 色(約束) | 寒色の夜 → 暖色の昼 |
| 編集のつなぎ | ハードカット → マッチカット → 暗転 |
さらに、**同じ技法を2場面で主役にしない**(専売化。設計書に「この場面だけ許可」と書く)。

## 6. 実例(これまでの作品で、どの技法をどこに使ったか)
- **30秒CM**: s1「百万の赤」=ネガティブスペース+スローな寄り+データの冷たさ(静)/ s2「対峙」=**ドリーズーム**+レイヤード・デプス+ラックフォーカス風のぼけ / s3「一撃」=**フリーズフレーム連打 → スマッシュカット(白→白黒反転)→ 画面が割れる(vfx-shatter的)→ スローモーションの余韻** / s5 カタログ=**クイックカット+モンタージュ**(各ショットで世界・技法を変える)/ s6 タイトル=ライトリーク・camera-shake・ハーフトーンの豪華 / s7「え？」=**固定カメラ+間(ま)**(動かさない笑い)/ s8 告知=**シンメトリー+静かなロー寄り**(荘厳)。
- **第1話**: e3 稲光=**ローキー+稲光のストロボ(光る瞬間だけ構図が見える)** / e4 廊下=**一点透視+前進ドリー** / e5 謁見=**ドリー+ボリュメトリック(光芒)+残像で消える** / e6 夕焼け=**ゴールデンアワー+クレーンアップ** / e7 オチ=**HUDのクローズアップ+グリッチ(情報の提示)**。

## 7. コードで再現しにくい技法の方針
- **実写の物理(レンズの歪み・実際の被写界深度・ドローン・手持ちの揺れ)** → 多層の疑似3D(CSS `perspective`+`translateZ`)、層ごとの `blur()`、seed付きノイズでの揺れ(camera-shake)で**同じ印象**を作る。各エントリの「HyperFramesでの作り方」に代替案がある。
- **AI生成映像前提(変身・分身・群衆・人物の浮遊など)** → ベクター/シルエット/UI/文字のアニメで同じ効果を狙う。「不向き」とあるエントリは代替案を読む。
- **再帰・フィードバック系**(エコー・フィードバック・ジェネレーティブ)は seek で壊れやすい → 閉形式の N世代重ね、または事前計算テーブルで書く(エントリ参照)。
- **既製部品**: `npx hyperframes catalog --query "<語>"` で実在確認してから `npx hyperframes add <名前>`。各エントリに載っている部品名は検証済み(`INDEX.md` 生成時に catalog と突き合わせている)。

## 8. 「効いているか」の確認(レビュー時)
- **カメラ**: 最後のコマに、最初のコマに無かった事実があるか。視差(近景が遠景より速くずれる)があるか(ただの拡大になっていないか)。
- **サイズ**: 切り替えたサイズが新しい事実を見せているか。直前と同じサイズが続いていないか。
- **光**: 光源は1つに決まっているか。最も明るい読めるものが、見せたいものか。
- **色**: 色の変化が「出来事」として起きているか。光源と整合しているか。
- **時間**: ランプ/フリーズを当てた拍が、物語の山か。通常速度でも成立するなら外す。
- **つなぎ**: 両側の絵を書いたか。共通要素(形・位置・動き・意味)が実際にあるか。
- **効果**: 物理的な原因を説明できるか(説明できないなら飾り)。
