## 1. 作ったもの
浮遊島の夜空を、光の気流に乗って荷物を届ける配達人のハイスピード・アクション(ローグライト+最大4人協力)。

| 2.0–4.0 | ゲーム画面風UIモック(配達数・ミニマップ・速度・チェイン・目的地)。光のゲートを拍ごとに3回くぐる → ランタンへクラッシュズーム |

| 8.0–9.75 | 特徴3「4人で協力配達」(4人のカードが順に立つ) |

## 3. 自己評価: 弱点(重要な順、利用者の目で厳しく)
1. **「ゲームの映像」に見えない/安っぽい(最大の弱点)**。浮遊島は逆三角形の平塗り、月は暗い円を重ねて作った三日月(暗い円の縁が背景のグローの上で見える)、配達人は 120px 程度の小さな記号。陰影・リムライト・質感がなく、ゲームの販促というより「解説用インフォグラフィック」の絵柄。戦う・避ける・危機などのゲームプレイの「事件」がない。
2. **主役とキービジュアルが無い**。配達人(主役)は S1・S2 でしか見えず、特徴とタイトルでは消える。ゲームPVで期待される「キャラの見せ場」「キーアート」が無い。持ち越す物(琥珀の灯り)は F1 まで(メーターへのグラフィックマッチ)で、F2・F3 で途切れた。
3. **ロゴが既製フォントを並べただけ**。Unbounded 900 の字間を広げた文字列+下線のスウッシュ。字形の加工・エンブレム・質感がなく、ロゴとしての記憶に残らない。着地の揺れと光の帯で動きは付いたが、絵としての格が足りない。
4. **タイポの質**。日本語見出しは Noto Sans JP 900 一択で個性が弱い。マスクリビール(#005)を6回使い、出方が単調。**特徴1〜3で説明文(2段目の下)が見出しより先に見えてしまう不具合**(下段の枠を2行分の高さにしたため、上から下りてくる2行目が最初から枠内に入る。4.0〜4.4 s など)。HUD のラベル・注記が 22〜26px で映像には小さい。和欧混植の行間・下線との間隔が詰まっている。
5. **特徴3場面が同じ型の繰り返し**(左に絵・右に見出し)。見出し位置の統一は business-motion-film の文法どおりだが、結果は「スライドの差し替え」に見える。F2→F3 はハードカットで、引き継ぐ物がない。
6. **場面転換の質**。ホイップパン(#043)は9枚の平均ブラーで、1920px では方向の流れでなく「半透明の重ね」に見え、S2 の HUD が残像で散らかる。色帯のトランジション(#018)は珊瑚・クリーム・青緑の大きな平面で、差し色1つ(琥珀)の約束を崩し、企業スライド風。
7. **色が単調で暗い**。紺〜藍の暗い背景が11秒以上続き、明度の山が 10.5 のタイトルしかない。グレイン(0.07)はほぼ見えない。
8. **音(測定から言えること)**: 打撃音の一部が下地に埋もれ、ドロップは出すぎ(上の表)。LRA 2.8 LU と幅が狭く、低域が 36% と多い(スマホでは -2.4 dB)。BGM は GM 音源のマリンバ+パッド+シンセベース。**音色の安っぽさ・曲としての良さは聴いていないので判断できない**(人の耳で確認してください)。
9. **情報の優先順位**。15秒に コピー・UI・特徴3つ・ロゴ・発売情報を詰めたため、各特徴の読める時間は約1.2秒、説明文(30px)はほぼ読めない。間(9.75–10.5)は 0.75 秒で、辞書の smash-cut の推奨(A を 1.2〜2.4 秒保持)より短い。
10. 細部: S2 の速度表示(最大 842)と F1(1,280)の数字がつながらない/HUD がばねで回転しながら出るので一瞬傾いて見える/光のレールが島を貫通している。

良かった点(参考): 120BPM の拍とカットの一致(頂点ずれ ±13ms 以内)、F1 のランタン→メーターの円のグラフィックマッチ、タイトル着地の揺れ(#024)、発売日のスクランブル確定(#129)、全体の配色の統一感、静止区間ゼロ。制作は速い(初稿まで約25分)。

## 5. 区別した所見

### A. スキルに従ったのに弱かった
- **motion-prompt のギャラリー中心(7〜8割)を守るほど、絵柄が「SaaS 解説」寄りになる**。ギャラリーの要素は UI・図解の動き(ポップ、棒グラフ、メーター、マスク見出し)で、ゲームPVの語彙(キャラのカットイン、ヒットストップ、ダメージ数字、ボス登場、ロゴスティンガー、画面割れ)が無い。被覆率79%は達成したが、質は上がらなかった。
- business-motion-film の文法(見出し位置の統一、原因→結果)は SaaS の発売映画から抽出した物で、ゲームでは「型の繰り返し」に見えた。
- #018 の色帯(4色)は「ブランド色で」とあるが、house-style の「差し色は1つ」と衝突。
- #043 の9枚平均ブラーは、カードの大きさ(539px)では効くが 1920px の全面では残像の重ねに見えた。
- 機械チェックは全部合格でも、絵の安っぽさは測れない(スキル自身も §2 で認めている)。審査役を立てられない時の代わりが無い。
- 音の設計ルール(3〜6 dB)に沿って置いたが、初稿では外れた(ゲインを自動で合わせる道具 solve-sfx-gains.py は 2D 枝の手順に組み込まれていない)。

### B. スキルに無くて困った
- **ゲームPV(トレーラー)の構成とお約束**: ゲームプレイの見せ方、キャラの見せ場、ロゴスティンガー、発売情報の表記(プラットフォームの書き方、レーティング、「開発中の画面です」の注記)。
- **2D のベクター絵を安く見せない描き方**(陰影・リムライト・グラデーション・質感・線)。`depth-and-texture.md` はあるが「未検証」で、2D枝の手順から参照されていない。
- **ロゴ(ロゴタイプ)の作り方**(字形の加工、エンブレム、SVG での質感)。
- **日本語の映像タイポ**(見出し用のフリー書体の選択肢、詰め、和欧混植、最小サイズと読了時間)。
- **canvas で描く時の HyperFrames の使い方**(check のコントラスト・レイアウト監査が canvas の中を見ない、全面 canvas は `canvas_covered` エラーになり `data-layout-allow-occlusion` が要る)。
- **日本語フォントのサブセット化の手順**(@fontsource の分割ファイルを unicode-range で必要分だけ取り出す処理を即席で書いた)。
- 他の担当を起動できない環境(サブエージェント)での、独立レビューの代わりの手順。

### C. スキルの記述が間違い・不親切だった点
- **Skill ツールで読み込まれる video-with-claude-code(`/root/.claude/skills/`)と、リポジトリの `SKILL.md` が別の版**(前者は旧版で分業を推奨、後者は担当1人)。どちらが正か、読む側には分からない。
- リポジトリの `SKILL.md` が参照する `docs/sound-upgrade/*.md`(earshot の導入手順など)が main に無い。1位の効果音の方法(Kenney+earshot)が再現できない。
- `SKILL.md` §3 の主手段 `video-by-reference` が、このセッションのスキル一覧に無い。
- 描画の枠組みの既定が3つの資料で食い違う: hyperframes「既定は HyperFrames」/ business-motion-film「例だけで HyperFrames を採らない」/ motion-prompt「空のフォルダなら Canvas の HTML 1枚」。
- `tools/audio_measure.py` の `--fps` の既定が 60。`SKILL.md` §5 のコマンド例に `--fps` が無く、30fps の動画で合図の時刻が半分になり、最初は誤った結果が出た。
- `tools/assemble.sh` は場面の mp4 を連結して再エンコードする前提で、1本の書き出しに使うと 451コマ(再エンコード)→ `-shortest` で 449コマになった。`-c:v copy` で手で結合し直して 450コマにした(機械的な修正)。
- `tools/sheet.sh` は画像を出力するが終了コード 2 を返す。
- `references/sfx-catalog.md` は「tick×3」のように個数だけで、実際の名前は `tick_001/002/004`(000 が無い)。推測した名前で KeyError。
- hyperframes の registry 部品 grain-overlay が `infinite` のアニメで、hyperframes-keyframes の「有限回」の決まりと矛盾。
- hyperframes は「書き出し前に Studio プレビューを開き承認を得る」を必須にしているが、無人のサブエージェントでの扱いが書かれていない。

### D. 呼べなかった・実施できなかったもの
- 独立レビュー(business-motion-film の gauntlet、SKILL.md §5-4 の②③): この担当には他の担当を起動する道具(Agent/Task)が無い。**この所見は作り手本人の自己評価で、独立ではない**。
- earshot(コードで描画する効果音): 未導入、導入手順の文書が main に無い。
- video-by-reference: スキル一覧に無い。
- `npx hyperframes usage`: `unsupported_auth` で不明。
- 音を聴くこと(AI は聴けない)。音の判断は測定値のみ。

## 7. 費用の目安と再現手順
- 時間: 読み込み〜初稿まで約25分(書き出し 1分38秒を含む)、所見の作成を含め約40分。
- トークン: 読んだ資料・画像を含む入力の累計で約20万トークン前後、出力は約4万トークン(目安。正確な値は記録から確認)。
- 再現:
  1. `cd examples/2d-game-promo && python3 make_audio.py && cp out/mix_raw.wav assets/audio/mix.wav`
  2. `npx hyperframes render --output render_raw.mp4 --fps 30 --crf 14`
  3. 音の音量: `tools/assemble.sh` と同じ2回通しの loudnorm(-14 LUFS / TP -2)で `soundtrack.wav` を作り、`ffmpeg -i render_raw.mp4 -i soundtrack.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k -ar 48000 -t 15 lumiwake_v1.mp4`
  4. `python3 ../../tools/review_checks.py lumiwake_v1.mp4`、`python3 ../../tools/audio_measure.py lumiwake_v1.mp4 --fps 30 --cues cues.json`
- フォントは `assets/fonts/`(SIL OFL、`LICENSE.md`)。GSAP は `assets/gsap.min.js`(3.14.2)を同梱。
